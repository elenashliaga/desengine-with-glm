Все работы в этом репозитории ведутся на русском языке, включая:
- требования и спецификации (OpenSpec),
- документацию,
- пользовательские тексты в интерфейсе,
- комментарии в коде (если они нужны).

Любые изменения поведения системы (новые возможности, изменения UX/потоков, новые API/контракты, ошибки и статусы) нужно фиксировать в OpenSpec-документации на русском языке:
- обновляя существующие спеки в `openspec/specs/`,
- и/или оформляя change в `openspec/changes/<name>/` с дельта-спеками.
- Новые changes в этом репозитории нужно создавать через `npm run openspec:new -- <name>`, а не через прямой `openspec new change`, чтобы в `.openspec.yaml` сразу появлялось поле `short`.

Короткая шпаргалка по именованию changes:
- использовать `kebab-case`;
- начинать имя с глагола: `add-...`, `fix-...`, `update-...`, `refactor-...`, `optimize-...`;
- одно имя change = одна главная идея;
- не использовать мусорные и слишком общие имена вроде `misc`, `cleanup`, `stuff`, `temp-fix`;
- не смешивать несколько тем в одном change-name;
- сразу после создания change заполнять `short` в `.openspec.yaml` как краткую аннотацию в 2-5 слов.

Если для change нужна отдельная ветка, и для его проработки, и для реализации нужно использовать одну и ту же ветку в формате `codex/<название-change>`.

Пока пользователь не сказал иначе, любые новые ветки нужно создавать от `main`.

Без явного отдельного распоряжения пользователя нельзя менять технический стек, критичный для установки и запуска проекта. Это ограничение распространяется в том числе на версии `Node.js`, сборщик проекта, `Turbopack` и прочие инфраструктурные и install-critical части. Такие изменения допустимы только если пользователь прямо сказал, что именно можно менять и как именно.

Любые тестовые прогоны и локальные браузерные проверки, включая `Playwright`, должны использовать `localhost`, а не `127.0.0.1`.

- Все кастомные UI-компоненты живут в `/components/desengine`.
- Нужно строго использовать `TypeScript`.
- Нужно предпочитать примитивы `shadcn/ui`.
- Нужно отделять рендеринг от логики playground/workbench.
- Не нужно инлайнить стили.
- Для учебных файлов нужно сохранять такое разделение:
  Component.tsx
  styles.ts
  mock.ts
  props.ts
  variants.ts
