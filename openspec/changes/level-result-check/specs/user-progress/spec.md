## MODIFIED Requirements

### Requirement: Прогресс хранится локально

Система SHALL хранить локально счётчик содержательных проверок текущего уровня и связанный checking-state.

#### Scenario: Пользователь запускает содержательную проверку уровня
- **WHEN** checking run возвращает валидный `passed / not passed`
- **THEN** локальный progress отражает, сколько содержательных проверок уже было использовано на этом уровне

#### Scenario: Проверка завершилась техническим сбоем
- **WHEN** checking run не состоялся технически
- **THEN** локальный progress не увеличивает счётчик содержательных проверок
- **AND** может отражать, что задача ждёт успешной проверки

### Requirement: Reset возвращает задачу в состояние `Не начиналась`

Система SHALL после последней допустимой неуспешной проверки возвращать задачу в то же начальное состояние, что и после обычного reset.

#### Scenario: Последняя допустимая проверка уровня неуспешна
- **WHEN** checking run исчерпал `maxCheckAttempts` уровня неуспешным содержательным результатом
- **THEN** система сбрасывает задачу к состоянию `Не начиналась`
- **AND** не сохраняет рабочее состояние этой задачи как продолжающееся

### Requirement: Удаление `user/` не ломает систему

Система SHALL трактовать одноразовый результат последней проверки как ephemeral user-owned данные, которые не делают систему хрупкой.

#### Scenario: После проверки пользователь удалил `user/`
- **WHEN** весь каталог `user/` отсутствует
- **THEN** система не требует старого результата проверки для запуска
- **AND** продолжает считать задачу не начатой
