## MODIFIED Requirements

### Requirement: У задачи есть канонический path-based маршрут

Система SHALL поддерживать отдельный path-based адрес результата проверки уровня.

#### Scenario: Пользователь открывает актуальный экран результата проверки
- **WHEN** у задачи есть актуальный одноразовый результат последней проверки
- **AND** пользователь открывает `/tasks/<taskId>/check`
- **THEN** система показывает страницу результата последней проверки уровня этой задачи

### Requirement: Экран результата проверки управляет дальнейшим движением по задаче

Система SHALL после запуска проверки уровня всегда приводить пользователя на отдельный экран результата проверки.

#### Scenario: Проверка уровня успешна
- **WHEN** checking run вернул успешный содержательный результат
- **THEN** система показывает страницу результата проверки
- **AND** с этой страницы пользователь может перейти к дальнейшему потоку этой же задачи

#### Scenario: Проверка уровня неуспешна
- **WHEN** checking run вернул неуспешный содержательный результат
- **THEN** система показывает страницу результата проверки
- **AND** с этой страницы пользователь может только вернуться в лабораторию

#### Scenario: Проверка уровня завершилась техническим сбоем
- **WHEN** checking run не выполнился из-за технической ошибки
- **THEN** система показывает страницу результата проверки
- **AND** с этой страницы пользователь может повторить проверку

#### Scenario: Последняя допустимая проверка провалена
- **WHEN** checking run вернул неуспешный содержательный результат и этим исчерпал лимит проверок уровня
- **THEN** система показывает страницу результата проверки
- **AND** сообщает, что задача была полностью сброшена
- **AND** не трактует задачу как продолжающуюся на этом уровне
