## MODIFIED Requirements

### Requirement: Итерация использует обязательные входные данные

Система SHALL использовать тот же набор level-разрешённых рабочих файлов и картинок не только для `iterate`, но и для checking run уровня.

#### Scenario: Пользователь запускает проверку уровня
- **WHEN** пользователь нажимает `Я закончил`
- **THEN** система включает в checking-контекст все рабочие файлы, разрешённые на текущем уровне
- **AND** все картинки текущего уровня, которые разрешены этим уровнем

### Requirement: Инициирующий запуск и уточнения используют одну модель

Система SHALL использовать тот же configured LLM-контур и для проверки результата уровня.

#### Scenario: Система выполняет checking run уровня
- **WHEN** система запускает проверку результата уровня
- **THEN** она использует тот же выбранный LLM-провайдер и тот же базовый инфраструктурный контур, что и для `start` и `iterate`

### Requirement: Ошибка итерации не разрушает текущее состояние

Система SHALL при техническом сбое checking run сохранять текущее состояние файлов и разрешать повторную проверку без списания попытки.

#### Scenario: Провайдер вернул ошибку при проверке
- **WHEN** checking run завершился сетевой ошибкой, ошибкой провайдера или невалидным structured-ответом
- **THEN** система не меняет рабочие файлы задачи
- **AND** не списывает попытку проверки
- **AND** показывает пользователю понятное сообщение с возможностью повторить проверку

### Requirement: Лимит уточняющих промптов больше не завершает уровень автоматически

Система SHALL трактовать `maxPromptsPerTask` только как ограничение на новые уточняющие промпты уровня, а не как самостоятельный критерий завершения уровня.

#### Scenario: Лимит уточняющих промптов исчерпан
- **WHEN** число использованных уточняющих промптов равно лимиту текущего уровня
- **THEN** система не запускает новую итерацию
- **AND** не завершает уровень автоматически
- **AND** сохраняет возможность пройти отдельную проверку результата уровня
