## MODIFIED Requirements

### Requirement: Ошибки LLM-провайдера объясняются пользователю

Система SHALL показывать пользователю понятные сообщения в случаях:
- отсутствует обязательная конфигурация провайдера;
- сетевые ошибки;
- таймауты;
- лимиты или ошибки провайдера;
- невалидный ответ (не удалось извлечь обновлённые файлы).

Для initiator-потока через OpenAI система SHALL поддерживать отдельный timeout и возвращать retriable-ошибку, если этот timeout превышен.

#### Scenario: Initiator-запрос к OpenAI превысил budget по времени
- **WHEN** скрытый initiator-запуск уровня не получил ответ от OpenAI за настроенный timeout
- **THEN** система прерывает вызов
- **AND** сохраняет текущее состояние задачи без частичных изменений
- **AND** показывает пользователю понятное сообщение, что initiator-запуск можно повторить

### Requirement: Инициирующий OpenAI-вызов диагностируется без утечки секретов

Система SHALL писать для initiator-потока минимальный диагностический след, достаточный для анализа latency и сбоев, не раскрывая API key и полный пользовательский контент.

Минимально диагностический след должен различать:
- старт вызова;
- успешный ответ провайдера;
- provider error;
- timeout;
- parse error;
- успешную запись файлов;
- сбой записи файлов.

#### Scenario: Разработчик анализирует медленный initiator-поток
- **WHEN** initiator-запрос к OpenAI завершился успехом или ошибкой
- **THEN** серверный лог содержит provider, model, target, число картинок, длину instruction, длительность вызова и исход операции
- **AND** лог не содержит raw API key
- **AND** лог не обязан содержать полный текст instruction или полный ответ модели
