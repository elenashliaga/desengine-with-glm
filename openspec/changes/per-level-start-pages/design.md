## Context

Текущая модель задачи смешивает два разных масштаба состояния:
- задача как целое имеет признак `started`;
- уровень имеет `currentLevelStatus` и `currentLevelInitialized`;
- при этом явная стартовая страница есть только для первого входа в задачу, а не для каждого уровня.

Это создаёт асимметрию:
- первый уровень фактически стартует через общий task-start;
- последующие уровни не имеют собственного одноразового начала;
- переход на новый уровень не отделяет достаточно ясно состояние “уровень уже открыт” от состояния “пользователь уже начал на нём работать”.

Пользовательский поток должен стать единообразным: любой уровень сначала открывается как ещё не начатый, затем пользователь явно запускает его со стартовой страницы, после чего система делает скрытый init и переводит в рабочий экран.

## Goals / Non-Goals

**Goals:**
- Сделать стартовую страницу обязательной для каждого уровня, включая первый.
- Явно разделить состояния “уровень открыт” и “уровень начат”.
- Убрать особый статус “задача вообще не начиналась” как самостоятельную сущность, сведя его к “не начат первый уровень”.
- Зафиксировать одноразовость стартовой страницы уровня.

**Non-Goals:**
- Финальная полировка точного surface flow страницы старта уровня.
- Изменение логики prompt-limit и завершения уровня.
- Полный редизайн task UI за пределами нового level-start flow.

## Decisions

- Каждый уровень имеет собственную стартовую страницу.
  - Это касается и первого уровня, и всех последующих.
  - Стартовая страница уровня показывается до рабочего экрана этого уровня.

- Новый уровень сначала считается открытым, но не начатым.
  - После завершения предыдущего уровня задача переходит на следующий уровень.
  - На новом уровне пользователь ещё не находится в рабочем состоянии, пока явно не запустит этот уровень.

- Явный старт уровня запускает hidden init-flow.
  - Поверхностно в этом change фиксируется такая модель:
    1. пользователь видит стартовую страницу уровня;
    2. нажимает действие начала уровня;
    3. система выполняет скрытый init-запуск;
    4. затем открывает рабочий экран уровня.
  - Этот surface flow может быть позже скорректирован отдельно, но пока считается каноническим.

- Стартовая страница уровня показывается только один раз на уровень.
  - Если уровень уже был начат и не завершён, следующий вход ведёт сразу в рабочий экран.
  - Повторный показ стартовой страницы для уже начатого уровня не является нормальным потоком.

- Статус “задача не начиналась вообще” становится производным.
  - Система больше не нуждается в отдельной независимой сущности “task never started”.
  - Эквивалентом такого состояния считается ситуация, когда первый уровень ещё не начат.

- Progress model должна хранить факт начала уровня отдельно от факта его завершения.
  - Текущих признаков `status` и `initializedAt` недостаточно как ясного пользовательского контракта.
  - В модели должен быть явно различим случай:
    - уровень текущий;
    - уровень открыт;
    - уровень ещё не начат.

## Pre-Implementation Checklist

- Проинвентаризировать текущие task-start и level-transition экраны.
- Проверить, где сейчас различаются `started`, `currentLevelStatus` и `currentLevelInitialized`.
- Зафиксировать новую summary-модель задачи для списка задач и рабочего экрана.
- Проверить reset и переходы уровней на совместимость с “не начат текущий уровень”.
- Проверить, что init уровня больше не стартует раньше явного начала уровня.

## Risks / Trade-offs

- [Смена модели старта] → можно случайно сломать текущую связку между task-start и hidden init → нужно централизованно переосмыслить start-flow, а не дописывать частичные условия.
- [Два масштаба статуса] → легко запутаться между “задача уже проходилась” и “текущий уровень ещё не начат” → change должен явно описывать оба слоя прогресса.
- [URL/route вопрос] → возможно, точный surface flow стартовой страницы уровня ещё поменяется → в этом change лучше зафиксировать поведение и инварианты, а не переобещать окончательную маршрутизацию.
