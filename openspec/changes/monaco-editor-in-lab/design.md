## Context

Сейчас пользователь редактирует код задачи через простую `textarea`. Для раннего прототипа это было достаточно, но в реальной лаборатории такой редактор слишком бедный: нет нормальной подсветки, неудобно работать с длинными файлами, сложнее воспринимать структуру кода и труднее переключаться между несколькими файлами как между частями одного программного артефакта.

Monaco Editor хорошо подходит под ожидаемый опыт: он даёт IDE-подобный редактор прямо в браузере и естественно ложится на сценарий работы с `Component.tsx`, `stories`, `styles`, `props` и `mock`.

## Goals / Non-Goals

**Goals:**
- Сделать Monaco основным редактором кода в лаборатории.
- Сохранить текущую модель “один активный файл из списка файлов задачи”, но улучшить сам experience редактирования.
- Сохранить совместимость с level-specific ограничениями `editableFileIds`.
- Избежать деградации UX при первой загрузке лаборатории.

**Non-Goals:**
- Полноценные IDE-фичи уровня language server, go-to-definition между всеми файлами и реальный TypeScript project graph на первом этапе.
- Одновременное редактирование нескольких файлов на одном экране.
- Diff-mode, inline review, collaboration cursors.

## Decisions

- Monaco становится основным редактором для всех редактируемых файлов лаборатории.
  - `textarea` не считается основным UI после этого change.

- Интеграция Monaco должна быть клиентской и lazy-loaded.
  - Редактор не должен утяжелять стартовую страницу `/` и не должен unnecessarily раздувать первый рендер вне лаборатории.

- Список файлов и модель переключения вкладок сохраняются.
  - Пользователь, как и раньше, работает с одним активным файлом за раз.
  - При переключении файла редактор должен корректно показывать содержимое текущего файла без потери локальных изменений в состоянии страницы.

- Language mode Monaco должен определяться по типу файла.
  - Минимально: TypeScript/TSX для компонентов и stories, TypeScript для `styles.ts`, `props.ts`, `mock.ts`, JSON для JSON-представлений, если они появятся.

- Должен существовать fallback на простой текстовый ввод.
  - Если Monaco не загрузился или упал, лаборатория не должна становиться неработоспособной.
  - Fallback может быть менее удобным, но обязан сохранять возможность редактирования.

- Интеграция не должна ломать current save model.
  - Существующий поток `изменил код → нажал Сохранить` остаётся валидным.
  - Monaco меняет только способ редактирования, а не общий жизненный цикл данных.

## Risks / Trade-offs

- [Тяжёлый клиентский бандл] → Monaco заметно тяжелее textarea → нужен lazy loading и изоляция редактора внутри лаборатории.
- [Сложности Next.js-интеграции] → Monaco требует аккуратной client-side интеграции → нужна реализация, безопасная для App Router и hydration.
- [Залипание состояния между вкладками] → при плохой интеграции можно терять несохранённые изменения или курсор → state редактора и state задачи должны оставаться синхронизированными.
- [Избыточность для маленьких файлов] → Monaco может казаться тяжёлым для простых правок → это допустимо, потому что лаборатория целится в experience “как в IDE”, а не в минимализм.
