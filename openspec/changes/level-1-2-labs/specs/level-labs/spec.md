## ADDED Requirements

### Requirement: Уровень 1 имеет собственную лабораторию

Система SHALL предоставлять отдельную лабораторию для уровня 1.

#### Scenario: Пользователь открывает задачу уровня 1
- **WHEN** пользователь открывает задачу на уровне 1
- **THEN** система открывает лабораторию уровня 1

### Requirement: Лаборатория уровня 1 показывает только base-картинку

Система SHALL показывать в лаборатории уровня 1 только `base.png`, заданную глобальным контрактом уровня 1.

#### Scenario: Открыта задача уровня 1
- **WHEN** лаборатория уровня 1 показывает визуальные вводные
- **THEN** система показывает `base.png`
- **AND** не показывает `variants.png`

### Requirement: Лаборатория уровня 2 имеет собственную лабораторию

Система SHALL предоставлять отдельную лабораторию для уровня 2.

#### Scenario: Пользователь открывает задачу уровня 2
- **WHEN** пользователь открывает задачу на уровне 2
- **THEN** система открывает лабораторию уровня 2

### Requirement: Лаборатория уровня 2 показывает base и variants

Система SHALL показывать в лаборатории уровня 2 обе картинки, заданные глобальным контрактом уровня 2: `base.png` и `variants.png`.

#### Scenario: Открыта задача уровня 2
- **WHEN** лаборатория уровня 2 показывает визуальные вводные
- **THEN** система показывает `base.png`
- **AND** показывает `variants.png`

### Requirement: Формат лаборатории уровня задаётся глобальным level-config

Система SHALL задавать для каждого уровня глобальный level-config, который определяет:
- список показываемых и отправляемых в инициирующий промпт картинок;
- список редактируемых файлов;
- идентификатор лаборатории уровня.

Линейные размеры картинок SHALL браться не из глобального level-config, а из task-specific конфигурации задачи по именованным типам картинок (`base`, `variants` и т.д.).

#### Scenario: Система загружает контракт лаборатории уровня
- **WHEN** система загружает данные задачи для конкретного уровня
- **THEN** она берёт общий формат лаборатории из глобального level-config этого уровня

### Requirement: Level-config имеет фиксированный минимальный shape

Система SHALL использовать для global level-config как минимум следующие поля:
- `levelId`;
- `labId`;
- `images[]` с элементами `{ id, show, sendToInitPrompt }`;
- `editableFileIds[]`;

#### Scenario: Система читает level-config уровня
- **WHEN** система загружает global level-config
- **THEN** она может определить по нему, какую лабораторию открыть, какие картинки показать, какие картинки отправить в инициирующий промпт и какие файлы разрешено редактировать

### Requirement: Каждый уровень хранится в собственной onboarding-папке

Система SHALL хранить данные каждого уровня в отдельной папке `onboarding/levels/<levelId>/`.

Внутри папки уровня SHALL существовать как минимум:
- `config.json` с компактным контрактом уровня;
- `overview.md` с общим пояснением уровня;
- `init-prompt.md` с initiator prompt уровня.

#### Scenario: Система загружает данные уровня
- **WHEN** система читает данные уровня `L`
- **THEN** она читает `config.json` из папки этого уровня
- **AND** читает общее пояснение из `overview.md`
- **AND** читает initiator prompt из `init-prompt.md`

### Requirement: JSON уровня не дублирует текстовые материалы

Система SHALL не хранить в `config.json` уровня большое общее описание уровня и initiator prompt.

#### Scenario: Разработчик открывает config уровня
- **WHEN** разработчик читает `onboarding/levels/<levelId>/config.json`
- **THEN** он видит только компактный контракт уровня
- **AND** не видит дублирования содержимого `overview.md` и `init-prompt.md`

### Requirement: Набор редактируемых файлов зависит от уровня

Система SHALL задавать список редактируемых файлов через global level-config уровня.

Для уровня 1 разрешены только:
- `Component.tsx`;
- `Component.stories.tsx`.

Для уровня 2 разрешены:
- `Component.tsx`;
- `Component.stories.tsx`;
- `styles.ts`.

#### Scenario: Пользователь открывает задачу уровня 1
- **WHEN** система показывает доступные для редактирования файлы уровня 1
- **THEN** пользователь может редактировать только `Component.tsx` и `Component.stories.tsx`

#### Scenario: Пользователь открывает задачу уровня 2
- **WHEN** система показывает доступные для редактирования файлы уровня 2
- **THEN** пользователь может редактировать `Component.tsx`, `Component.stories.tsx` и `styles.ts`

### Requirement: У задачи остаётся task-specific пояснение уровня

Система SHALL хранить отдельно от глобального level-config уникальное для задачи пояснение текущего уровня.

#### Scenario: Пользователь открывает конкретную задачу на уровне
- **WHEN** система показывает лабораторию уровня
- **THEN** она показывает общее пояснение уровня
- **AND** task-specific пояснение этой задачи

### Requirement: Task config хранит размеры картинок и пояснения по уровням

Система SHALL хранить в task-specific конфигурации задачи:
- размеры картинок по именованным типам (`base`, `variants` и т.д.);
- task-specific пояснения по уровням.

#### Scenario: Система загружает task-specific данные задачи
- **WHEN** система открывает задачу на конкретном уровне
- **THEN** она берёт размеры нужных картинок из task config
- **AND** берёт task-specific пояснение текущего уровня из task config
