## Context

До сих пор уровень задачи был в первую очередь дидактической осью: лимиты, переходы, общий layout и общие материалы. Но как только уровень 1 и уровень 2 начинают использовать разные картинки и разные требования к инициирующему запуску, уровень становится ещё и источником глобального контракта лаборатории.

При этом не вся level-specific информация должна дублироваться в каждой задаче. Если для всех задач уровня формат лаборатории одинаковый, то нет смысла заводить отдельный каталог и отдельный `config.json` внутри каждой задачи только ради одинаковых правил. Лучше разделить:
- что задаётся уровнем глобально;
- что остаётся уникальным для конкретной задачи.

## Goals / Non-Goals

**Goals:**
- Зафиксировать разные лаборатории для уровня 1 и уровня 2.
- Зафиксировать разные визуальные вводные и разные инициирующие промпты для этих уровней.
- Зафиксировать глобальный level-config для первых двух уровней.
- Зафиксировать task-specific часть level-specific контента без избыточных каталогов и конфигов.

**Non-Goals:**
- Немедленная детализация лабораторий уровней 3+.
- Полное описание всех будущих asset types для уровней.
- Немедленный перенос задач во внешний didactics-repo в рамках этого change.

## Decisions

- Уровень 1 и уровень 2 получают отдельные лаборатории.
  - Это не один и тот же экран с условным `if`, а два разных level-specific сценария работы.

- Формат лаборатории уровня задаётся глобально для уровня.
  - Для каждого уровня фиксируются:
    - список показываемых и отправляемых в инициирующий промпт картинок;
    - линейные размеры этих картинок;
    - список файлов, которые пользователю разрешено редактировать и подключать к уточняющим промптам;
    - общее пояснение уровня;
    - инициирующий промпт уровня.
  - Причина: для всех задач одного уровня этот контракт одинаков.
- Глобальный level-config должен быть компактным и ссылочным, а не содержать большие тексты inline.
  - Хранение уровня должно быть файловым: `levels/<level-id>/config.json` плюс соседние файлы уровня в той же папке.
  - Предлагаемый shape:
    ```json
    {
      "levelId": 1,
      "labId": "level-1",
      "images": [
        { "id": "base", "show": true, "sendToInitPrompt": true }
      ],
      "editableFileIds": ["Component.tsx", "Component.stories.tsx"]
    }
    ```
  - Для уровня 2 меняются `labId`, `images` и `editableFileIds`.
  - Общее пояснение уровня хранится только в `levels/<level-id>/overview.md`.
  - Инициирующий промпт уровня хранится в `levels/<level-id>/init-prompt.md`.
  - Оба markdown-файла должны существовать у каждого уровня, даже если один из них пока пустой.
  - `config.json` не хранит `description` и другие большие текстовые материалы уровня.
  - JSON уровня остаётся компактным и не содержит большие тексты inline.

- Задача хранит только task-specific часть level-specific контента.
  - На текущем этапе это как минимум уникальное пояснение задачи на данном уровне.
  - Нет смысла заводить для этого отдельный каталог уровня внутри каждой задачи, если остальные правила уровня общие.
- Task-specific конфиг задачи остаётся плоским.
  - Предлагаемый shape:
    ```json
    {
      "images": {
        "base": { "width": 320, "height": 240 },
        "variants": { "width": 640, "height": 240 }
      },
      "levelTaskNotes": {
        "1": "Уникальное пояснение задачи для уровня 1",
        "2": "Уникальное пояснение задачи для уровня 2"
      }
    }
    ```
  - Поле `images` хранит task-specific размеры по именованным типам картинок.
  - Поле `levelTaskNotes` хранит только уникальные пояснения задачи по уровням.

- На уровне 1 глобальный level-config задаёт `base.png` и размеры `base`.
  - На уровне 1 пользователю разрешено редактировать только `Component.tsx` и `Component.stories.tsx`.
  - Инициирующий промпт уровня 1 просит сверстать именно картинку `base`.

- На уровне 2 глобальный level-config задаёт `base.png`, `variants.png` и размеры `base` и `variants`.
  - На уровне 2 к редактируемым файлам добавляется `styles.ts`.
  - Инициирующий промпт уровня 2 просит дополнить вёрстку первой картинки по второй.
  - В промпте явно фиксируется, что вторая картинка является параметризованной первой и что результат должен быть получен именно параметризацией исходной вёрстки.

- Level-specific промпты должны храниться и выбираться по уровню.
  - Это касается как минимум скрытого инициирующего промпта.
  - Такой подход не мешает потом вынести дидактику во внешний репозиторий.

- На текущем этапе `levelTaskNotes` достаточно как единственного обязательного task-specific поля уровня.
  - Этого хватает, чтобы отделить общий контракт лаборатории от уникального контекста конкретной задачи без появления level-каталогов внутри каждой задачи.
  - Если позже понадобится больше task-specific данных, их можно добавлять рядом, не ломая текущую схему.

- Следующие task-specific поля можно добавить позже без перехода к отдельным level-каталогам:
  - `levelTaskHints` для коротких подсказок уровня;
  - `levelTaskConstraints` для дополнительных ограничений по задаче;
  - `levelTaskChecks` для task-specific критериев самопроверки.
  - Все они должны оставаться плоскими словарями по номеру уровня, как и `levelTaskNotes`.

- Совместимость с будущим didactics-repo сохраняется.
  - Глобальный `level-config` уже разложен по папкам уровней и не смешивает большие тексты с JSON-конфигурацией.
  - Task-specific часть сведена к компактному JSON рядом с задачей.
  - При выносе дидактики наружу достаточно перенести level-specific тексты и prompts по ключам, не меняя shape задач.

## Risks / Trade-offs

- [Разделение глобального и task-specific] → можно ошибиться, что является общим для уровня, а что уникально для задачи → поэтому level-config должен хранить только действительно одинаковые правила уровня.
- [Слишком бедная task-specific модель] → позже может оказаться, что кроме task-specific пояснения нужны и другие уникальные поля → это допустимо, если они будут добавляться адресно, без преждевременной каталогизации.
- [Два источника конфигурации] → часть правил живёт в level-config, часть в task config → имена image ids должны быть едиными (`base`, `variants`, и т.д.), иначе они не состыкуются.
- [Разъезд промптов и UI] → если уровень меняет картинки, но не меняет prompt selection, поведение станет неочевидным → поэтому выбор лаборатории и инициирующего промпта должен зависеть от уровня из одного и того же источника.
