## Context

Уровни являются общей образовательной осью продукта. Они одинаковы для всех задач как типы, но конкретная задача принадлежит только одному уровню. Не все уровни обязаны иметь задачи. Для каждого уровня существуют собственные:
- дидактический промпт;
- внешний вид лаборатории;
- общий обучающий контент;
- лимит промптов на одну задачу.

Это означает, что уровень — не просто “настройка” задачи, а отдельный слой продукта со своей лабораторией и своей дидактикой.
Уточнение модели: одна и та же задача может существовать на нескольких уровнях сложности последовательно. Пользователь не получает “новую задачу следующего уровня”, а продолжает ту же самую задачу, переходя на уровень `L+1`.

## Goals / Non-Goals

**Goals:**
- Зафиксировать единую модель уровней для всех задач.
- Развести понятия “уровень как слой продукта” и “задача как единица работы”.
- Описать правила прогресса и завершения задачи на уровне.
- Подготовить основу для level-specific лабораторий и контента.

**Non-Goals:**
- Реализация конкретных экранов лаборатории для каждого уровня.
- Реализация конкретных дидактических промптов.
- Точная редакторская структура материалов уровня.
- Алгоритм автоматической оценки качества результата задачи.

## Decisions

- Уровни глобальны для всей системы как типы образовательной работы.
  - Они имеют общие идентификаторы (`level-1`, `level-2`, ...).
  - Количество уровней ограничено сверху организационно, сейчас ориентир — не более 20.
  - Их дидактика, layout и общий контент одинаковы для всех задач, которые дошли до этого уровня.

- Каждая задача имеет собственный максимум `maxLevel`.
  - Это означает, что задача существует на уровнях от `1` до `maxLevel`.
  - Не каждая задача обязана доходить до всех глобальных уровней.

- Пользователь проходит одну и ту же задачу последовательно по уровням.
  - Завершив задачу на уровне `L`, пользователь переходит на уровень `L+1` этой же задачи, если он существует.
  - Переход не должен быть мгновенным: сначала показывается отдельный экран перехода.
  - Переключение на произвольный уровень задачи запрещено.
  - Если у задачи нет уровня `L+1`, задача считается исчерпанной по своей траектории.

- Лаборатория определяется уровнем.
  - На практике это означает, что `layout`, доступные блоки, пояснения, действия и подача могут полностью отличаться между уровнями.
  - Следовательно, архитектурно нужно считать уровни разными лабораториями, а не “тем же экраном с парой флажков”.

- Общий контент уровня открывается, как только в системе есть хотя бы одна задача, у которой существует этот уровень.
  - Контент уровня не привязан к конкретной задаче.
  - Пользователь может читать материалы уровня отдельно от конкретной задачи.

- Завершение уровня задачи задаётся двумя механизмами:
  - пользователь вручную говорит “Я закончил”;
  - либо исчерпывается лимит промптов для уровня на эту задачу.

- Лимит промптов задаётся на уровне.
  - Для каждого уровня есть число `maxPromptsPerTask`.
  - Оно применяется одинаково ко всем задачам этого уровня.

## Risks / Trade-offs

- [Слишком разные лаборатории] → если лаборатории уровней разойдутся слишком сильно, возрастёт стоимость поддержки → нужно заранее думать о shared primitives и общей оболочке.
- [Неясность завершения] → ручное “Я закончил” и лимит промптов не гарантируют качества результата → на MVP это допустимо, но позже может понадобиться оценка качества.
- [Задачи имеют разную глубину] → пользователи будут сталкиваться с тем, что часть задач продолжается дальше, а часть уже закончилась → это нужно явно показывать в прогрессе.
- [Лимит промптов жёсткий] → у некоторых пользователей лимит может заканчиваться слишком рано → лимит нужно хранить как явную настройку уровня, а не как константу.
