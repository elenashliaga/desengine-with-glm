## ADDED Requirements

### Requirement: Уровни являются глобальными для всей системы

Система SHALL поддерживать общий каталог уровней, единый для всех задач.

#### Scenario: Система описывает уровень
- **WHEN** система создаёт или читает уровень
- **THEN** уровень идентифицируется глобальным `levelId`, не зависящим от конкретной задачи

### Requirement: Каждая задача имеет собственный диапазон уровней

Система SHALL хранить для каждой задачи её максимальный доступный уровень `maxLevel`.

#### Scenario: Система читает описание задачи
- **WHEN** система загружает метаданные задачи
- **THEN** системе известен диапазон уровней задачи от `1` до `maxLevel`

### Requirement: Пользователь проходит одну и ту же задачу по уровням последовательно

Система SHALL переводить пользователя внутри одной и той же задачи с уровня `L` на уровень `L+1`, если следующий уровень существует.

#### Scenario: Пользователь завершил задачу на текущем уровне
- **WHEN** пользователь успешно завершил задачу на уровне `L`
- **THEN** система открывает для этой же задачи уровень `L+1`, если он существует

### Requirement: Переход на следующий уровень проходит через отдельный экран

Система SHALL показывать отдельный экран перехода перед открытием следующего уровня той же задачи.

#### Scenario: У задачи есть следующий уровень
- **WHEN** пользователь успешно завершил задачу на уровне `L`, и у этой задачи существует уровень `L+1`
- **THEN** система сначала показывает экран перехода, а затем открывает уровень `L+1`

### Requirement: Экран перехода имеет минимальный фиксированный набор действий

Система SHALL показывать на экране перехода между уровнями одной и той же задачи ровно два действия:
- `Решать эту же задачу дальше`
- `Перейти в список задач`

#### Scenario: Пользователь видит экран перехода
- **WHEN** пользователь попал на экран перехода после завершения уровня
- **THEN** система показывает ссылку на продолжение этой же задачи и ссылку на список задач

### Requirement: Уровень определяет лабораторию

Система SHALL определять внешний вид и структуру лаборатории по уровню задачи.

#### Scenario: Пользователь открывает задачу уровня
- **WHEN** пользователь открывает задачу уровня `L`
- **THEN** система показывает лабораторию, соответствующую уровню `L`

### Requirement: Уровень имеет собственный дидактический промпт

Система SHALL связывать каждый уровень с собственным дидактическим промптом.

#### Scenario: Пользователь запускает итерацию по задаче уровня
- **WHEN** пользователь запускает итерацию по задаче уровня `L`
- **THEN** система использует дидактический промпт уровня `L`

### Requirement: Уровень имеет лимит промптов на задачу

Система SHALL хранить для каждого уровня настройку `maxPromptsPerTask`.

#### Scenario: Пользователь работает над задачей уровня
- **WHEN** пользователь запускает промпты по задаче уровня `L`
- **THEN** система считает промпты относительно лимита `maxPromptsPerTask` уровня `L`

### Requirement: Завершение уровня требует успешной проверки результата

Система SHALL считать задачу уровня завершённой только после успешной проверки результата этого уровня.

#### Scenario: Пользователь говорит “Я закончил”
- **WHEN** пользователь запускает действие `Я закончил`
- **THEN** система переводит задачу в checking-flow
- **AND** не считает уровень завершённым только по самому нажатию кнопки

#### Scenario: Проверка результата уровня успешна
- **WHEN** checking run вернул успешный содержательный результат
- **THEN** система переводит задачу в статус завершённой

### Requirement: Лимит промптов не завершает уровень автоматически

Система SHALL трактовать `maxPromptsPerTask` только как ограничение на новые уточняющие промпты уровня.

#### Scenario: Лимит промптов исчерпан
- **WHEN** пользователь исчерпал лимит промптов по задаче уровня
- **THEN** система не разрешает новый уточняющий промпт
- **AND** не переводит задачу в статус завершённой только по этой причине

### Requirement: Если следующего уровня нет, задача заканчивается на текущем уровне

Система SHALL считать задачу исчерпанной, если пользователь успешно завершил её на максимальном уровне этой задачи.

#### Scenario: Пользователь завершил задачу на максимальном уровне
- **WHEN** пользователь успешно завершил задачу на уровне, равном `maxLevel`
- **THEN** система не открывает для этой задачи следующий уровень

### Requirement: Текущий уровень имеет отдельное рабочее состояние

Система SHALL различать как минимум состояние текущего, но ещё не начатого уровня, состояние уровня в работе, состояние ожидания повторной проверки и завершённый уровень.

#### Scenario: Пользователь перешёл на новый уровень, но ещё не начал его
- **WHEN** предыдущий уровень уже завершён, а новый уровень ещё не запускался
- **THEN** система считает новый уровень текущим
- **AND** не считает его начатым автоматически

#### Scenario: Технический сбой проверки требует повторной проверки
- **WHEN** checking run завершился техническим сбоем
- **THEN** система сохраняет текущий уровень как не завершённый
- **AND** переводит его в состояние ожидания повторной проверки

### Requirement: Общий контент уровня не зависит от конкретной задачи

Система SHALL поддерживать отдельный контент уровня, общий для всех задач этого уровня.

#### Scenario: В системе есть хотя бы одна задача, дошедшая до уровня
- **WHEN** в системе есть хотя бы одна задача, у которой `maxLevel >= L`
- **THEN** общий контент уровня `L` может быть показан независимо от выбранной задачи

### Requirement: Контент уровня может быть доступен без открытия конкретной задачи

Система SHALL позволять пользователю читать контент уровня, даже если он не находится внутри конкретной задачи этого уровня.

#### Scenario: Пользователь открывает раздел уровня
- **WHEN** пользователь открывает материалы уровня `L`
- **THEN** система показывает контент уровня `L` без обязательного открытия конкретной задачи
