## Why

Сейчас при первом редактировании файла в лаборатории первый введённый символ может теряться. Баг проявляется в самый чувствительный момент UX: пользователь только начинает печатать, интерфейс переводит файл в состояние с несохранёнными изменениями и показывает кнопку `Сохранить`, после чего фактическое содержимое редактора оказывается неполным.

Нужно зафиксировать контракт исправления так, чтобы первый ввод не терялся ни при первом переходе в dirty-state, ни при первом показе действия `Сохранить`.

## What Changes

- Уточняем контракт лаборатории уровня: первый ввод в редактируемом файле MUST сохраняться полностью.
- Фиксируем, что переход файла в состояние с несохранёнными изменениями и появление кнопки `Сохранить` не должны обрезать, откатывать или перезаписывать первый пользовательский ввод.
- Распространяем это требование на основной редактор и fallback-режим редактирования.
- Добавляем регрессионное покрытие в существующий единый слой тестирования с канонической командой запуска для этого сценария.

## Capabilities

### New Capabilities

- Нет.

### Modified Capabilities

- `level-labs`: поведение редактора уточняется так, чтобы первый пользовательский ввод не терялся при первом переходе файла в состояние несохранённых изменений.

## Impact

- UI: потребуется скорректировать синхронизацию состояния между `LabWorkbench`, кодовой панелью и редактором, чтобы индикация dirty-state не вмешивалась в первый ввод.
- Редактор: потребуется проверить одинаковое поведение в Monaco и fallback-редакторе.
- Тесты: потребуется добавить регрессионный сценарий в существующий `Vitest`/browser-контур и зафиксировать команду запуска без внешних credentials и без нестабильных данных.
