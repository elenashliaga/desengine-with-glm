## Context

Сейчас у уровня уже есть `overview.md`, но по требованиям продукта это не должен быть просто сырой текст. Уровень — это образовательный слой, а значит его описание должно уметь не только показывать абзацы, но и содержать ссылки, изображения и другую markdown-структуру. Параллельно у уровня должна быть явная точка выхода на дополнительные материалы.

## Goals / Non-Goals

**Goals:**
- Добавить в level-config явную ссылку на дополнительные материалы.
- Сделать `overview.md` полноценным markdown-источником страницы уровня.
- Поддержать в описании уровня как минимум ссылки и картинки.

**Non-Goals:**
- Полноценный CMS-редактор материалов уровня.
- Расширенный интерактивный контент внутри markdown beyond обычного HTML-рендера.
- Отдельная сложная система хранения медиа вне текущего файлового формата.

## Decisions

- В конфиг уровня добавляется явное поле URL для дополнительных материалов.
  - Оно задаёт внешний или внутренний переход к расширенному контенту уровня.

- `overview.md` уровня рендерится как Markdown, преобразованный в HTML.
  - Это означает, что в level overview поддерживаются заголовки, абзацы, списки, ссылки, картинки и базовая markdown-структура.

- Страница уровня не должна показывать markdown как сырой plain text.
  - Пользователь видит уже готовую HTML-разметку.

- Поддержка картинок и ссылок считается обязательной частью markdown-render.
  - Это особенно важно для дидактического контента, где иллюстрации и переходы к материалам являются нормальной частью объяснения.

## Risks / Trade-offs

- [Небезопасный markdown-render] → при прямом HTML-рендере можно случайно открыть XSS-вектор → нужен контролируемый markdown pipeline.
- [Смешение overview и внешних материалов] → часть контента окажется и в `overview.md`, и по URL → нужно считать `overview.md` краткой встроенной частью, а URL — расширением.
- [Ломкие пути к картинкам] → markdown-изображения должны разрешаться согласованно относительно структуры уровня.
