## Why

Сейчас кнопка `Я закончил` мгновенно завершает уровень и переводит задачу дальше. Это не даёт системе проверить, действительно ли результат соответствует учебным условиям уровня.

Нужна отдельная фаза проверки результата:
- пользователь явно запускает её действием `Я закончил`;
- система отправляет в LLM специальный hidden checking prompt уровня вместе со всеми разрешёнными файлами и картинками уровня;
- пользователь всегда попадает на отдельную страницу результата проверки;
- только успешная проверка завершает уровень и открывает путь дальше.

Дополнительно нужно зафиксировать limit-политику проверок: уровень может ограничивать число содержательных проверок, а исчерпание этого лимита после неуспешной проверки должно сбрасывать задачу полностью.

## What Changes

- Фиксируем отдельную проверочную фазу для каждого уровня задачи.
- Фиксируем hidden prompt `onboarding/prompts/levels/<levelId>/check.md`.
- Фиксируем, что проверка использует все `editableFileIds` текущего уровня и все разрешённые картинки уровня.
- Фиксируем, что успешная проверка сразу завершает уровень.
- Фиксируем, что неуспешная проверка не завершает уровень и отправляет пользователя обратно в лабораторию.
- Фиксируем отмену старого правила “исчерпан лимит уточняющих промптов = уровень завершён”.
- Фиксируем лимит `maxCheckAttempts` в `onboarding/levels/<levelId>/config.json`.
- Фиксируем, что технический сбой проверки не тратит попытку и оставляет задачу в состоянии `Ждёт проверки`.
- Фиксируем, что последняя допустимая неуспешная содержательная проверка сбрасывает задачу полностью, но одноразовая страница результата всё равно сообщает о причине этого сброса.
- Фиксируем более содержательную роль страницы перехода на следующий уровень: показать, что удалось на предыдущем уровне, и чего хочет следующий уровень.

## Capabilities

### Modified Capabilities
- `task`: задача получает отдельную страницу результата проверки уровня и новый переход после `Я закончил`.
- `task-levels`: завершение уровня теперь проходит через LLM-проверку и учитывает лимит проверок.
- `iteration`: LLM-контур получает отдельный checking run помимо `start` и `iterate`.
- `llm`: система использует hidden checking prompt уровня и структурированный ответ проверки.
- `onboarding-repo`: onboarding-уровень хранит hidden checking prompt и structured setting `maxCheckAttempts`.
- `user-progress`: прогресс хранит число содержательных проверок уровня и их результативный контур.

## Impact

- Runtime: потребуется отдельный endpoint и отдельная result-page модель для проверки уровня.
- Progress model: потребуется хранить счётчик содержательных проверок, состояние ожидания проверки и одноразовый результат последней проверки.
- Onboarding model: уровню понадобится `check.md` и `maxCheckAttempts`.
- UX: `Я закончил` перестаёт быть мгновенным завершением уровня и становится запуском верификации результата.
