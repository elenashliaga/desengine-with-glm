## MODIFIED Requirements

### Requirement: Пользователь проходит одну и ту же задачу последовательно

Система SHALL считать уровень завершённым только после успешной проверки результата уровня.

#### Scenario: Пользователь нажал `Я закончил`
- **WHEN** пользователь на текущем уровне запускает действие `Я закончил`
- **THEN** система запускает проверку результата уровня
- **AND** ещё не считает уровень завершённым только по самому нажатию кнопки

#### Scenario: Проверка уровня успешна
- **WHEN** checking run вернул `passed = true`
- **THEN** система немедленно завершает текущий уровень задачи
- **AND** только после этого открывает дальнейший flow перехода

#### Scenario: Исчерпан лимит уточняющих промптов уровня
- **WHEN** число использованных уточняющих промптов достигло лимита текущего уровня
- **THEN** система не считает уровень завершённым только по этой причине
- **AND** сохраняет необходимость отдельной успешной проверки уровня

### Requirement: Экран перехода на следующий уровень объясняет прогресс задачи

Система SHALL использовать экран `/tasks/<taskId>/next` как содержательный переход между уровнями одной и той же задачи.

#### Scenario: Пользователь успешно завершил уровень и попал на `/next`
- **WHEN** предыдущий уровень успешно пройден
- **THEN** экран перехода формулирует, что было достигнуто на предыдущем уровне
- **AND** показывает актуальную демку или результат этого уровня
- **AND** формулирует, чего ожидает следующий уровень этой же задачи
- **AND** использует task-specific `tip.md` этой задачи для предыдущего и следующего уровня, если такие файлы существуют

### Requirement: Каждый уровень ограничивает число содержательных проверок

Система SHALL хранить для каждого уровня число допустимых содержательных проверок `maxCheckAttempts`.

#### Scenario: Система читает конфиг уровня
- **WHEN** система загружает `onboarding/levels/<levelId>/config.json`
- **THEN** ей известно ограничение `maxCheckAttempts` для этого уровня

#### Scenario: Проверка завершилась техническим сбоем
- **WHEN** checking run не дал содержательного ответа
- **THEN** система не уменьшает остаток допустимых проверок уровня

#### Scenario: Проверка завершилась содержательным ответом
- **WHEN** checking run вернул валидный `passed / not passed`
- **THEN** система учитывает это как одну проверку уровня

### Requirement: Исчерпание допустимых проверок после fail сбрасывает задачу

Система SHALL полностью сбрасывать задачу, если последняя допустимая содержательная проверка уровня завершилась неуспешно.

#### Scenario: Обычная неуспешная проверка при оставшихся попытках
- **WHEN** checking run вернул `passed = false`
- **AND** у уровня ещё остаются допустимые проверки
- **THEN** система не завершает уровень
- **AND** сохраняет задачу на текущем уровне

#### Scenario: Последняя допустимая проверка уровня неуспешна
- **WHEN** checking run вернул `passed = false`
- **AND** это была последняя допустимая содержательная проверка уровня
- **THEN** система полностью сбрасывает задачу
- **AND** возвращает её к начальному состоянию
