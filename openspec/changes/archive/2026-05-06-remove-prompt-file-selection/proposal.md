## Why

Сейчас уточняющий промпт всё ещё предполагает, что пользователь выбирает, какие файлы отправлять в контекст LLM. Это закреплено сразу в нескольких местах:
- в спеках;
- в UI уточняющего промпта;
- в API-контракте `iterate`;
- в истории уточнений через `selectedFileIds`.

Но по смыслу продукта это уже лишняя сложность:
- на каждом уровне и так есть явный allowlist файлов через `editableFileIds`;
- backend уже умеет по умолчанию брать все разрешённые файлы текущего уровня;
- дополнительный пользовательский выбор создаёт лишний UI-шум и ненужное решение для пользователя.

Команда хочет упростить этот поток: уточняющий промпт всегда идёт со всеми файлами, доступными пользователю на текущем уровне, а сам UI уточнения сводится к одному полю ввода.

## What Changes

- Фиксируем, что уточняющий промпт всегда получает в контекст все рабочие файлы, разрешённые на текущем уровне.
- Фиксируем, что пользователь больше не выбирает подмножество файлов для `iterate`.
- Фиксируем, что UI уточняющего промпта состоит только из текстового поля ввода и действия запуска.
- Фиксируем, что API-контракт уточняющего промпта больше не требует `selectedFileIds` от клиента.
- Фиксируем, что история уточнений больше не должна зависеть от пользовательского выбора файлов как от отдельного действия.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `iteration`: контекст уточняющего промпта всегда включает все level-разрешённые рабочие файлы.
- `component-file-set`: пользователь больше не управляет подмножеством вводных файлов для итерации.
- `task`: интерфейс уточнения задачи упрощается до текстового поля и запуска.

## Impact

- UI: блок выбора файлов в уточняющем промпте уйдёт из product-shell интерфейса.
- API: `iterate` перестанет принимать пользовательский список выбранных файлов как часть официального контракта.
- Specs/history: нужно синхронно убрать модель “выбранных вводных файлов” из актуального пользовательского потока.
