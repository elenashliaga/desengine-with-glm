## ADDED Requirements

### Requirement: Уточняющие запросы нумеруются при сохранении уровневого лимита

Система SHALL нумеровать уточняющие запросы в рамках одной задачи, начиная с 1, и SHALL сохранять действующую уровневую модель лимита `maxPromptsPerTask`.

#### Scenario: Пользователь отправляет очередной уточняющий запрос
- **WHEN** у задачи уже есть `N` сохранённых уточняющих запросов
- **THEN** новый запрос получает номер `N + 1`

#### Scenario: Лимит уточняющих запросов текущего уровня исчерпан
- **WHEN** пользователь уже израсходовал весь лимит `maxPromptsPerTask` текущего уровня
- **THEN** система не позволяет отправить ещё один уточняющий запрос на этом уровне

### Requirement: История уточняющих запросов отображается в прямом порядке

Система SHALL показывать историю уточняющих запросов в порядке их выполнения: от первого к последнему.

#### Scenario: Пользователь просматривает историю уточнений
- **WHEN** у задачи есть несколько уточняющих запросов
- **THEN** система показывает сначала самый ранний запрос, а затем все последующие

### Requirement: История уточнений содержит полный контекст отображения

Система SHALL показывать для каждого уточняющего запроса:
- его порядковый номер,
- дату и время в формате `YYYY-MM-DD HH:mm:ss`,
- список файлов, отправленных в контекст,
- список файлов, реально изменённых результатом итерации,
- кнопку копирования текста запроса.

#### Scenario: Пользователь открывает историю после нескольких итераций
- **WHEN** пользователь просматривает карточку ранее выполненного уточняющего запроса
- **THEN** система показывает текст запроса, дату в формате `YYYY-MM-DD HH:mm:ss`, отправленные файлы и изменённые файлы
- **AND** рядом с текстом есть кнопка «Скопировать»

### Requirement: Стоимость уточнений считается по фиксированной ставке

Система SHALL считать условную стоимость каждого уточняющего запроса равной 3 центам и SHALL показывать суммарную стоимость решения задачи как учебный индикатор.

Этот индикатор SHALL быть отделён от реальных токеновых или денежных метрик LLM-провайдера и SHALL не подменять их.

#### Scenario: Пользователь выполнил несколько уточнений
- **WHEN** у задачи сохранено `N` уточняющих запросов
- **THEN** система показывает суммарную стоимость `N * 3` цента
- **AND** эта ставка не зависит от модели, размера ответа или других параметров

#### Scenario: Провайдер не вернул реальные метрики
- **WHEN** у итерации нет токеновых или денежных метрик от LLM-провайдера
- **THEN** учебный индикатор стоимости всё равно отображается отдельно
- **AND** интерфейс не выдаёт его за реальные метрики провайдера
