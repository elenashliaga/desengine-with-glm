## Why

Сейчас интерфейс самого инструмента стилизуется смешанно:
- часть общих основ лежит в `app/globals.css`;
- часть повторяемых решений живёт в локальных `styles.ts`;
- заметная доля визуальных решений прописана прямо inline в `app/**` и `components/desengine/**` длинными Tailwind-строками.

Из-за этого product-shell интерфейс трудно поддерживать как единую систему: одни и те же карточки, панели, секции, заголовки, ссылки и состояния собираются по месту заново, а граница между “общим UI-языком инструмента” и “локальной особенностью конкретного компонента” остаётся размытой.

Нужен единый Tailwind-слой именно для интерфейса инструмента, без вмешательства в учебный контент из `/onboarding/**`, пользовательские рабочие файлы из `/user/**` и без переноса всего подряд в глобальный CSS.

## What Changes

- Фиксируем единый Tailwind CSS-файл для общего визуального языка интерфейса инструмента.
- Фиксируем, что product-shell маршруты и компоненты должны в первую очередь использовать общие semantic-классы из этого файла, а не дублировать длинные inline class string.
- Фиксируем, что локальные `styles.ts` остаются только для по-настоящему индивидуальной композиции конкретного компонента.
- Фиксируем явное исключение для `/onboarding/**`, `/user/**` и прочих пользовательских/генерируемых рабочих файлов.
- Фиксируем миграцию существующих повторяющихся shell-паттернов в общий UI-слой без смены install-critical стека.

## Capabilities

### Modified Capabilities
- `ui-foundation`: интерфейс инструмента получает единый Tailwind-слой и правила распределения общих и локальных стилей.

## Impact

- UI consistency: общий визуальный язык интерфейса станет централизованным и предсказуемым.
- DX: новые product-shell экраны будет проще собирать без копирования длинных class string.
- Refactoring: потребуется инвентаризация повторяющихся shell-паттернов и перенос их в единый stylesheet.
- Review: у команды появится более чёткий критерий, что считается общим UI-слоем, а что локальной деталью компонента.
