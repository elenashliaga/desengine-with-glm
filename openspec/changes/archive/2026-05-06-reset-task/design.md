## Context

Сейчас система умеет начинать задачу, накапливать рабочие файлы и историю уточнений, но не умеет возвращать задачу в исходное состояние одной операцией. Для учебного сценария это неудобно: пользователю может понадобиться пройти тот же уровень заново, сравнить подходы или просто очистить неудачный результат.

## Goals / Non-Goals

**Goals:**
- Добавить явное действие полного сброса задачи.
- Зафиксировать, какие файлы сохраняются, а какие удаляются.
- Зафиксировать очистку истории уточняющих запросов и возврат задачи в статус `Не начиналась`.

**Non-Goals:**
- Частичный сброс только отдельных файлов.
- Восстановление старых версий после reset.
- Изменение стартовых артефактов задачи в рамках reset.

## Decisions

- Reset является явной пользовательской операцией на уровне конкретной задачи.
- При reset сохраняются только стартовые артефакты задачи: `base`, `variants` и `config`.
- Все сгенерённые и рабочие файлы задачи удаляются.
- История уточняющих запросов задачи очищается полностью.
- После reset задача считается не начатой и снова проходит обычный стартовый сценарий при следующем открытии.

## Risks / Trade-offs

- [Потеря данных] → reset удаляет рабочий результат без возможности отката → интерфейсу нужно явное подтверждение действия.
- [Несогласованное состояние] → если удалить файлы, но не очистить историю или статус, задача останется в полусброшенном состоянии → reset должен обновлять файлы, историю и статус как одну операцию.
- [Разные форматы стартовых артефактов] → по мере развития уровней стартовый набор может уточняться → источник правды о сохраняемых стартовых файлах должен быть централизованным, а не размазанным по коду.
