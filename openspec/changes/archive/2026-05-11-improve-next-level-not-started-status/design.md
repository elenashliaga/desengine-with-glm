## Context

В текущей модели уже существует важное различие между двумя слоями состояния:
- задача в целом уже может считаться начатой;
- текущий уровень при этом может ещё не иметь `initializedAt`, промптов и статуса `in_progress`.

На сервере это различие выражается косвенно через сочетание нескольких полей, но стартовая страница задач не использует его как самостоятельный пользовательский сигнал. В результате сценарий “предыдущий уровень завершён, новый текущий ещё не начат” теряется внутри общего текста `Уровень N из M`.

## Goals / Non-Goals

**Goals:**
- Явно зафиксировать переходный статус следующего уровня в OpenSpec.
- Сделать его отдельным читаемым состоянием в summary прогресса.
- Обновить стартовую страницу задач без ломки существующих статусов и переходов.
- Покрыть логику unit-тестами на уровне summary и presentation helper-ов.

**Non-Goals:**
- Редизайн стартовой страницы задач.
- Изменение маршрутизации task-flow.
- Пересмотр логики hidden start, checking-state или reset.

## Decisions

- Summary прогресса получает derived-флаг `currentLevelNotStarted`.
  - Он вычисляется как отрицание факта старта текущего уровня.
  - Это не заменяет `currentLevelStarted`, а делает переходный сценарий явным для UI и тестов.

- Стартовая страница задач показывает отдельные тексты для не начатого текущего уровня.
  - Основной статус: `Уровень N из M ещё не начат`.
  - Бейдж: `Уровень N не начат`.
  - Подсказка по уточнениям сообщает, что уровень ещё не стартовал и сколько уточнений будет доступно после старта.

- Остальные статусы не меняются.
  - `Не начиналась` остаётся только для задачи, где не начат первый уровень.
  - `Ждёт проверки` остаётся при `checkingState = awaiting_retry`.
  - Обычный активный уровень продолжает показываться как `Уровень N из M`.
  - Полностью завершённая задача продолжает показываться как завершённая.

## Risks / Trade-offs

- [Дублирование derived-состояния] Новый флаг частично пересекается с `currentLevelStarted`, но делает контракт UI гораздо понятнее и снижает риск расползания условной логики по компонентам.
- [Текстовая регрессия] Изменение пользовательских строк может случайно задеть штатные статусы, поэтому нужны отдельные тесты на presentation helper-ы.
