## Why

Сейчас система LLM-настроек оформлена непоследовательно: для разных провайдеров используются разные схемы имён, часть provider-specific параметров несёт префикс ``, а для OpenAI базовый URL ещё и отличается по схеме именования и имеет скрытый fallback в коде. Это ломает единый mental model администрирования и противоречит идее общего LLM-слоя, в котором провайдеры должны настраиваться одинаково.

Нужно выровнять контракт так, чтобы у всех поддерживаемых LLM-провайдеров был единый набор параметров подключения, provider-specific env-параметры не использовали префикс ``, а сетевые адреса не были захардкожены в адаптерах как скрытая часть runtime-поведения.

## What Changes

- Уточняем общий контракт `llm`: каждый провайдер MUST настраиваться через единообразные env-параметры как минимум для `api key`, `model` и `base URL`.
- Фиксируем, что provider-specific LLM-параметры именуются без префикса ``.
- Фиксируем единый naming-паттерн для `base URL` и `model` без исключения для OpenAI.
- Запрещаем скрытые hardcoded `base URL` внутри адаптеров как источник фактической runtime-конфигурации.
- Добавляем задачу на согласование документации и проверок конфигурации для всех провайдеров.

## Capabilities

### New Capabilities

- Нет.

### Modified Capabilities

- `llm`: общий контракт конфигурации LLM-провайдеров уточняется так, чтобы provider-specific `model` и `base URL` задавались единообразно для OpenAI, DeepSeek и Google Gemini без префикса `` и без скрытых адресов в коде.

## Impact

- Runtime-конфигурация: потребуется унифицировать provider-specific env-переменные и убрать special-case вокруг OpenAI.
- Документация: понадобится обновить `desengine.config-example.txt`, `docs/openai.md`, `docs/deepseek.md`, `docs/gemini.md` и связанные подсказки статуса системы.
- Тесты и smoke-проверки: потребуется добавить проверку, что конфиг-поведение всех провайдеров согласовано и не зависит от hardcoded URL в коде.
