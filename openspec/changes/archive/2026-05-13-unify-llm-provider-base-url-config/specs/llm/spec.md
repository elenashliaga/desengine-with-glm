## MODIFIED Requirements

### Requirement: LLM-настройки задаются через локальные переменные окружения

Система SHALL хранить рабочие LLM-настройки лаборатории в локальных переменных окружения, а не в пользовательских данных задач.

Система SHALL использовать одну и ту же модель для инициирующего запуска уровня и для обычных уточняющих запросов.
Система SHALL брать имя модели только из `desengine.config.txt` или эквивалентных env vars процесса, а не из `desengine.config.json`.

Для каждого поддерживаемого провайдера система SHALL задавать конфигурацию подключения единообразно: через отдельные env-параметры для ключа доступа, модели и `base URL`.

Provider-specific env-параметры модели и `base URL` SHALL именоваться без префикса ``.

Система SHALL не использовать скрытый hardcoded `base URL` внутри адаптера как фактический источник runtime-конфигурации провайдера.

#### Scenario: Пользователь меняет модель для лаборатории
- **WHEN** пользователь перенастраивает LLM для лаборатории
- **THEN** он делает это через `desengine.config.txt` или эквивалентные env vars процесса
- **AND** новая настройка одинаково влияет и на `start`, и на `iterate`

#### Scenario: В desengine.config.json нет настройки модели
- **WHEN** приложение читает инфраструктурный `desengine.config.json`
- **THEN** оно не ищет там имя OpenAI-модели
- **AND** выбор модели полностью определяется локальной env-конфигурацией запуска

#### Scenario: Оператор задаёт параметры активного провайдера
- **WHEN** оператор выбирает активный провайдер через `LLM_PROVIDER`
- **THEN** он может задать для этого провайдера ключ доступа, модель и `base URL` через локальный env-конфиг
- **AND** адаптер использует именно эти параметры без изменений в коде

#### Scenario: Оператор настраивает provider-specific модель
- **WHEN** оператор задаёт модель активного провайдера в локальном env-конфиге
- **THEN** он использует имя переменной без префикса ``
- **AND** система не требует provider-specific имени модели в форме `<PROVIDER>_MODEL`

#### Scenario: Для активного провайдера не задан обязательный base URL
- **WHEN** пользователь запускает LLM-действие без обязательного `base URL` текущего провайдера
- **THEN** система показывает понятное сообщение о неполной конфигурации
- **AND** не подставляет скрытый сетевой адрес из кода вместо явной настройки

#### Scenario: Оператор настраивает provider-specific base URL
- **WHEN** оператор задаёт `base URL` активного провайдера в локальном env-конфиге
- **THEN** он использует имя переменной без префикса ``
- **AND** система не требует provider-specific имени `base URL` в форме `<PROVIDER>_BASE_URL`

### Requirement: Конфиги нескольких провайдеров не конфликтуют

Система SHALL позволять хранить настройки нескольких LLM-провайдеров в одном `desengine.config.txt`, если активный провайдер выбран явно.

#### Scenario: В конфиге лежат несколько провайдеров
- **WHEN** в `desengine.config.txt` одновременно присутствуют ключи, модели и `base URL` для OpenAI, DeepSeek и Google Gemini
- **THEN** система использует только параметры активного провайдера из `LLM_PROVIDER`
- **AND** наличие неактивных provider-specific переменных не ломает запуск
