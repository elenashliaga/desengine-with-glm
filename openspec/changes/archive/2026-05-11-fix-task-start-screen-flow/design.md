## Контекст

Текущая проблема не в модели данных уровня, а в смешении двух разных действий:
- навигации пользователя к задаче;
- фактического старта текущего уровня с hidden init-run.

Серверный route `POST /api/tasks/<taskId>/start` уже реализует нужную семантику явного старта уровня: подготавливает рабочие файлы, запускает скрытый initiator-flow и помечает текущий уровень как начатый. Ошибка возникает раньше, в `TasksScreen`, где домашняя кнопка `Начать` вызывает этот route вместо обычного перехода на task-route.

## Решение

1. Кнопка `Начать` на `/tasks` должна выполнять только `router.push("/tasks/<taskId>")`.
2. Страница `/tasks/<taskId>` продолжает использовать уже существующую развилку:
   - если `currentLevelStarted === false`, показывается `TaskLevelStart`;
   - если `currentLevelStarted === true`, открывается `LabWorkbench`.
3. Кнопка `Начать уровень` на `TaskLevelStart` остаётся единственной точкой, где вызывается `POST /api/tasks/<taskId>/start`.

## Почему этого достаточно

- Для новой задачи `task.started === false`, поэтому переход на `/tasks/<taskId>` откроет стартовую страницу первого уровня без побочных эффектов.
- Для задачи, у которой открыт новый уровень после успешной проверки предыдущего, `currentLevelStarted === false`, поэтому тот же task-route снова покажет стартовую страницу уже нового уровня.
- Для уже начатой задачи `currentLevelStarted === true`, поэтому `Продолжить` и прямой вход в `/tasks/<taskId>` сохраняют рабочий экран без лишних промежуточных шагов.

## Проверки

- Проверить OpenSpec-артефакты change.
- Проверить ручкой и через браузерный сценарий:
  - `Начать` на `/tasks` не вызывает преждевременный start-route;
  - на `/tasks/<taskId>` виден `TaskLevelStart`;
  - `Начать уровень` запускает hidden init-run и переводит на рабочий экран;
  - уже начатая задача по `Продолжить` открывается как раньше.
