## Why

Сейчас кнопка `Начать` на `/tasks` вызывает `/api/tasks/<taskId>/start` напрямую. Из-за этого пользователь с домашнего списка задач пропускает стартовую страницу уровня и сразу запускает скрытый initiator-flow. Такое поведение расходится с актуальными OpenSpec `task` и `task-levels`, где:
- `Начать` на `/tasks` должна открывать стартовую страницу первого или текущего уровня;
- скрытый init-run должен запускаться только после явного подтверждения на этой стартовой странице;
- следующий уровень после успешной проверки должен открываться как текущий, но ещё не начатый.

Нужно вернуть flow к этой модели, не ломая уже работающий рабочий экран, переходы между уровнями и повторные открытия начатых задач.

## What Changes

- Разделяем навигацию на стартовую страницу уровня и фактический запуск уровня.
- Меняем кнопку `Начать` на `/tasks`, чтобы она открывала `/tasks/<taskId>` без немедленного POST на start-route.
- Оставляем hidden init-run только за явным действием `Начать уровень` на стартовой странице уровня.
- Уточняем OpenSpec change-артефактами, что стартовая страница уровня является обязательной точкой входа для старта уровня.

## Impact

- UX стартовой страницы задач станет согласованным со стартовой страницей уровня.
- Риск регрессии сосредоточен в сценариях старта/продолжения задачи и перехода на новый уровень после успешной проверки.
- Существующий API `/api/tasks/<taskId>/start` остаётся рабочим, но используется только из level start screen.
