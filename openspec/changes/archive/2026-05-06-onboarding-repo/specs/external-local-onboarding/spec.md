## MODIFIED Requirements

### Requirement: Локально установленная система умеет явно сигнализировать о недоступности onboarding-контента

Система SHALL в официальном локальном сценарии запуска уметь явно показывать статус проблемы, если onboarding-контент не был подгружен.

#### Scenario: Пользователь запускает систему без доступного `/onboarding`
- **WHEN** локальный запуск произошёл без доступного onboarding-контента
- **THEN** система запускается
- **AND** явно сообщает, что onboarding-контент недоступен

### Requirement: Локальная конфигурация хранит адрес onboarding-репозитория

Система SHALL хранить адрес onboarding-репозитория в `config.txt` как часть локальной конфигурации запуска через переменную `DESENGINE_ONBOARDING_REPO_URL`.

#### Scenario: Оператор настраивает источник onboarding-контента
- **WHEN** оператор задаёт, откуда брать onboarding-контент
- **THEN** он делает это через `config.txt`
- **AND** указывает значение в `DESENGINE_ONBOARDING_REPO_URL`

### Requirement: Локальная система читает onboarding-контент только из `/onboarding`

Система SHALL в этой фазе локальной миграции читать onboarding-контент только из `/onboarding` и явно сигнализировать о проблеме, если каталог отсутствует или неполон.

#### Scenario: Локальная установка ещё не получила полный `/onboarding`
- **WHEN** пользователь запускает продукт без полного onboarding-контента в `/onboarding`
- **THEN** система не переключается на старые корневые каталоги
- **AND** явно показывает проблему с onboarding-контентом

### Requirement: Локальная установка обновляет onboarding-контент вручную с `/config`

Система SHALL предоставлять на `/config` ручное действие `Обновить onboarding` как единственную явную точку обновления локального onboarding-контента.

#### Scenario: Оператор хочет обновить локальный onboarding-контент
- **WHEN** оператор открывает `/config`
- **THEN** он видит действие `Обновить onboarding`
- **AND** может обновить onboarding-контент вручную через это действие
