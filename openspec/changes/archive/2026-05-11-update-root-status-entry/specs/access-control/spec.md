## MODIFIED Requirements

### Requirement: Доступ в систему требует актуального allowlist-допуска

Система SHALL считать пользователя допущенным к защищённой части продукта только при наличии актуального allowlist-допуска, не распространяя это требование на публичный корневой маршрут `/`.

#### Scenario: Пользователь открывает защищённую часть системы без допуска
- **WHEN** пользователь пытается открыть защищённый пользовательский маршрут без успешной allowlist-проверки
- **THEN** система переводит его на `/auth`

#### Scenario: Пользователь открывает публичный корень без допуска
- **WHEN** пользователь без допуска открывает `/`
- **THEN** система не переводит его на `/auth`
- **AND** показывает публичную страницу состояния системы
