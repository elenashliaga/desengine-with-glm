## MODIFIED Requirements

### Requirement: Доступ в систему проверяется по email до начала работы

Система SHALL требовать ввод email до допуска пользователя к лаборатории и заданиям.

#### Scenario: Пользователь открывает защищённую часть системы без допуска
- **WHEN** пользователь пытается открыть защищённый пользовательский маршрут без успешной allowlist-проверки
- **THEN** система переводит его на `/auth`

### Requirement: После допуска пользователь возвращается на целевой path

Система SHALL возвращать пользователя после успешного допуска на тот path, который он пытался открыть, без использования query-параметра `next`.

#### Scenario: Пользователь шёл на защищённый экран задачи
- **WHEN** пользователь без допуска пытается открыть path внутри защищённой части продукта
- **THEN** система сохраняет целевой path вне пользовательского URL
- **AND** после успешного допуска возвращает пользователя именно на этот path

#### Scenario: Возвратный path невалиден
- **WHEN** сохранённый path отсутствует, повреждён или не относится к разрешённым пользовательским маршрутам
- **THEN** после успешного допуска система открывает безопасный канонический маршрут по умолчанию
