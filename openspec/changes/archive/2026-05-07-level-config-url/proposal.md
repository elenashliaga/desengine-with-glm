## Why

Сейчас level-config хранит основные открытые свойства уровня, но в нём нет отдельного поля для URL, связанного с уровнем. Если такой адрес нужен как часть открытого контракта уровня, его приходится либо не хранить вовсе, либо выводить из внешних соглашений.

Нужен явный параметр URL в конфиге уровня, который может быть задан, а может оставаться пустым.

## What Changes

- Фиксируем, что level-config поддерживает отдельное поле `url`.
- Фиксируем, что это поле относится к открытому уровневому контуру и хранится в `onboarding/levels/<levelId>/config.json`.
- Фиксируем, что значение `url` может быть пустым.
- Фиксируем, что отсутствие URL не делает уровень невалидным.

## Capabilities

### Modified Capabilities
- `level-labs`: открытый конфиг уровня получает дополнительное поле `url`.
- `task-levels`: каталог уровней поддерживает явный URL-параметр уровня как часть его метаданных.

## Impact

- Content model: потребуется расширить shape level-config.
- Runtime/types: потребуется обновить схему и типы уровня.
- UI integration: отдельным шагом можно будет решать, где именно использовать этот URL в интерфейсе.
