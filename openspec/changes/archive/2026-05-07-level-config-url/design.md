## Context

Текущий level-config уже хранит открытые свойства уровня: идентификатор, номер, название, описание, лимиты, layout и другие метаданные. После разделения открытого и скрытого контуров уровня логично держать дополнительные открытые ссылки тоже внутри level-config, а не в скрытом prompt-слое и не во внешних соглашениях.

Сейчас такого поля нет, поэтому change нужен как чистое расширение открытого контракта уровня.

## Goals / Non-Goals

**Goals:**
- Добавить в открытый level-config параметр `url`.
- Разрешить пустое значение URL без поломки уровня.
- Зафиксировать это как часть level metadata, не смешивая с hidden prompt-контуром.

**Non-Goals:**
- Зафиксировать обязательное использование URL в конкретном экране интерфейса.
- Валидировать достижимость внешнего адреса.
- Превращать URL в обязательное поле для всех уровней.

## Decisions

- Поле называется `url`.
  - Оно хранится в `onboarding/levels/<levelId>/config.json`.
  - Оно относится к открытому контракту уровня.

- Поле `url` может быть пустым.
  - Допустимы пустая строка или отсутствие значения как эквивалент “для этого уровня адрес не задан”.
  - Отсутствие URL не должно делать уровень невалидным.

- Change пока фиксирует только хранение и типовой контракт.
  - Где и как этот URL показывается пользователю, можно уточнить отдельным change или последующей реализацией.

## Pre-Implementation Checklist

- Обновить схему level-config и типы уровня.
- Проверить загрузку levels catalog на совместимость с отсутствующим URL.
- Убедиться, что отсутствие URL не ломает текущие страницы уровней и задач.

## Risks / Trade-offs

- [Неопределённый UI-смысл] → если не зафиксировать хотя бы базовый storage-контракт, URL будет продолжать жить во внешних договорённостях → этот change сознательно вводит сначала storage/model слой.
- [Пустое поле] → разные части системы могут по-разному трактовать пустой URL → нужно прямо закрепить, что пустое значение допустимо и не считается ошибкой.
