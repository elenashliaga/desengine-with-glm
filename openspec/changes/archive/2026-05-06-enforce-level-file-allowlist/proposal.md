## Why

Сейчас у уровней уже есть понятие разрешённых файлов через `editableFileIds`, и интерфейс задачи в основном уважает это ограничение. Но этого недостаточно для реального файлового контракта уровня:
- LLM всё ещё может вернуть файл, который на этом уровне запрещён;
- backend может физически записать такой файл на диск;
- на диске могут оставаться “лишние” файлы от предыдущего уровня или старой итерации;
- в результате фактическое состояние задачи может расходиться с тем, что уровень разрешает пользователю видеть и редактировать.

Команда хочет искусственно ужесточить этот контракт: на каждом уровне задача должна содержать только те рабочие файлы, которые для этого уровня разрешены.

## What Changes

- Фиксируем, что `editableFileIds` уровня становятся не только UI-ограничением, но и жёстким файловым allowlist.
- Фиксируем, что при `start` и `iterate` система создаёт и обновляет только разрешённые для текущего уровня файлы.
- Фиксируем, что если LLM вернул запрещённый файл, система игнорирует его и не создаёт на диске.
- Фиксируем, что перед продолжением работы система отдельно проверяет диск и удаляет рабочие файлы, которые запрещены на текущем уровне.
- Фиксируем, что это правило особенно важно для переходов между уровнями, когда на более раннем уровне часть файлов ещё не разрешена.

## Capabilities

### New Capabilities
- Нет.

### Modified Capabilities
- `component-file-set`: допустимый набор рабочих файлов становится level-aware и enforce-ится на записи.
- `task-levels`: каждый уровень определяет не только UI-набор файлов, но и фактический набор файлов на диске.
- `iteration`: результаты LLM-прогона применяются только в пределах разрешённого файлового allowlist текущего уровня.

## Impact

- Runtime/backend: потребуется фильтровать payload от LLM перед записью файлов.
- File system hygiene: потребуется отдельный шаг очистки запрещённых файлов на диске.
- Level transitions: переходы между уровнями должны автоматически приводить рабочую директорию задачи к разрешённому набору файлов текущего уровня.
- Debugging/observability: полезно будет явно видеть, какие файлы были проигнорированы или удалены как запрещённые для уровня.
