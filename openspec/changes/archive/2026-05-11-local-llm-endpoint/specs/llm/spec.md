## MODIFIED Requirements

### Requirement: На MVP используется настраиваемый LLM-провайдер

Система SHALL использовать на MVP тот LLM-провайдер, который выбран конфигурацией приложения.

Поддерживаются как минимум два режима:
- облачный провайдер по ключу;
- Ollama по URL.

#### Scenario: Конфигурация выбрала облачный провайдер
- **WHEN** приложение настроено на облачный режим
- **THEN** система отправляет LLM-запросы в облачный провайдер по ключу

#### Scenario: Конфигурация выбрала Ollama
- **WHEN** приложение настроено на режим Ollama
- **THEN** система отправляет LLM-запросы в настроенный Ollama endpoint

### Requirement: Ключ не попадает в слепки и репозиторий

Система SHALL хранить и использовать ключ облачного провайдера так, чтобы он не попадал:
- в публичные слепки,
- в репозиторий (включая коммиты),
- в пользовательские сообщения об ошибках по умолчанию.

Система SHALL поддерживать сценарий работы без облачного ключа, если выбран режим Ollama.

#### Scenario: Пользователь публикует слепок
- **WHEN** пользователь публикует слепок
- **THEN** ключ не включается в слепок

#### Scenario: Система работает через Ollama
- **WHEN** выбран режим Ollama
- **THEN** отсутствие облачного ключа не мешает запуску LLM-вызовов

### Requirement: Ошибки LLM-провайдера объясняются пользователю

Система SHALL показывать пользователю понятные сообщения в случаях:
- отсутствует обязательная конфигурация провайдера;
- сетевые ошибки;
- таймауты;
- лимиты или ошибки провайдера;
- невалидный ответ (не удалось извлечь обновлённые файлы).

#### Scenario: Провайдер вернул ошибку
- **WHEN** провайдер вернул ошибку
- **THEN** пользователь видит понятное сообщение и может повторить итерацию

#### Scenario: Конфигурация провайдера неполная
- **WHEN** пользователь запускает действие, требующее LLM, без обязательных параметров текущего провайдера
- **THEN** система показывает понятное сообщение о том, каких параметров не хватает

### Requirement: Учёт затрат ведётся на итерацию и на задание

Система SHALL вести учёт затрат или доступных метрик провайдера минимум на уровне:
- итерация (один запуск),
- задание (сумма по итерациям).

Если выбранный провайдер не возвращает денежные или токеновые метрики, система SHALL явно фиксировать отсутствие этих данных и не подменять их вымышленными значениями.

#### Scenario: Пользователь выполнил несколько итераций через облачный провайдер
- **WHEN** пользователь выполнил несколько итераций в рамках задания
- **THEN** система показывает агрегированные затраты по заданию

#### Scenario: Пользователь выполнил несколько итераций через Ollama
- **WHEN** провайдер не возвращает денежные или токеновые метрики
- **THEN** система сохраняет факт итераций без вымышленных значений стоимости
