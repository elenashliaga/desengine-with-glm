## ADDED Requirements

### Requirement: Система поддерживает Ollama по URL

Система SHALL поддерживать Ollama, доступную по URL на локальной машине или в локальной сети.

#### Scenario: Оператор выбирает Ollama
- **WHEN** конфигурация приложения переключена в режим Ollama
- **THEN** система использует для LLM-вызовов настроенный Ollama endpoint вместо облачного провайдера по ключу

### Requirement: Ollama задаётся явной конфигурацией

Система SHALL брать параметры подключения к Ollama из конфигурации приложения, а не зашивать их в код.

#### Scenario: Оператор настраивает Ollama
- **WHEN** оператор задаёт параметры Ollama в локальной конфигурации
- **THEN** система использует эти параметры без изменения кода

### Requirement: Минимальная конфигурация Ollama фиксирована

Система SHALL считать минимальной конфигурацией Ollama:
- базовый URL;
- имя модели;
- таймаут запроса.

#### Scenario: Конфигурация Ollama неполная
- **WHEN** для режима Ollama не хватает обязательных параметров
- **THEN** система не запускает LLM-вызов и показывает понятную ошибку конфигурации

### Requirement: Ollama проверяется до основной работы

Система SHALL уметь проверить доступность Ollama до запуска старта задачи или итерации.

#### Scenario: Пользователь открывает лабораторию с Ollama
- **WHEN** система выполняет проверку доступности Ollama
- **THEN** пользователь получает отдельный статус готовности или понятную ошибку подключения

### Requirement: Ошибки Ollama различаются по типам

Система SHALL различать как минимум следующие классы ошибок Ollama:
- отсутствует обязательная конфигурация;
- endpoint недоступен по сети;
- запрос завершился таймаутом;
- endpoint вернул неподдерживаемый или невалидный ответ.

#### Scenario: Endpoint в локальной сети недоступен
- **WHEN** система не может установить соединение с Ollama endpoint
- **THEN** пользователь видит ошибку недоступности endpoint, а не абстрактное сообщение о сбое

### Requirement: Другие локальные системы добавляются отдельными адаптерами

Система SHALL трактовать поддержку других локальных или сетевых LLM-систем как отдельные будущие адаптеры, а не как часть текущего Ollama change.

#### Scenario: Появляется новая локальная LLM-система
- **WHEN** команда хочет подключить не Ollama, а другую локальную систему
- **THEN** это оформляется отдельным change с отдельным адаптером и отдельными требованиями
