## Context

Сейчас пользователю нужен полноценный домашний экран продукта. По мере появления уровней, старта задач, продолжения и reset нужен отдельный обзорный экран, где все задачи видны сразу и где основные действия доступны без лишнего погружения в рабочий экран задачи.

При этом на этом этапе не нужно ломать существующую внутреннюю маршрутизацию задач и уровней: стартовая страница просто становится новым верхним слоем навигации.

## Goals / Non-Goals

**Goals:**
- Сделать `/tasks` стартовой страницей пользователя со списком задач.
- Показать все задачи в компактном вертикальном списке.
- Дать по каждой задаче рабочие действия `Начать`, `Продолжить`, `Сбросить`.
- Показать текущий уровень и компактный горизонтальный индикатор уровня.

**Non-Goals:**
- Полный пересмотр всех пользовательских маршрутов.
- Богатый каталог задач с фильтрами, поиском и группировками.
- Отдельная карточная витрина задач вместо компактного списка.

## Decisions

- Стартовая страница пользователя появляется в `/tasks`.
  - При этом `/` остаётся отдельной точкой входа и явно переводит пользователя на `/tasks`.
  - Рабочие экраны задач и уровней продолжают жить на своих актуальных маршрутах.

- Список задач сортируется по коду задачи.
  - Это даёт стабильный и предсказуемый порядок без дополнительных пользовательских настроек.

- Строка задачи строится как компактный горизонтальный layout.
  - Слева — название задачи как ссылка на продолжение решения.
  - Далее — либо кнопка `Начать`, либо номер уровня.
  - Между номером уровня и индикатором располагается кнопка `Продолжить`.
  - Справа от индикатора — кнопка `Сбросить` только для начатой задачи.

- Для не начатой задачи вместо номера уровня показывается `Начать`.
  - Для не начатой задачи кнопка `Сбросить` не показывается.
  - При этом ссылка с названия задачи всё равно ведёт в рабочий экран этой задачи.

- Горизонтальный индикатор уровня является обзорным, а не точной шкалой обучения.
  - Он должен визуально показывать, что более высокий уровень длиннее более низкого.
  - На этом этапе не требуется сложная аналитическая визуализация или отдельная легенда.

- Все действия на стартовой странице являются рабочими.
  - `Начать` действительно запускает задачу.
  - `Продолжить` действительно открывает нужную задачу.
  - `Сбросить` действительно сбрасывает задачу.

## Risks / Trade-offs

- [Перегруженная строка задачи] → в одной строке много действий и индикаторов → нужен жёстко компактный, но читаемый layout.
- [Дублирование действия перехода] → и название задачи, и кнопка `Продолжить` ведут в задачу → это допустимо, потому что название — это навигационная ссылка, а кнопка — явный action.
- [Reset рядом с основными действиями] → можно случайно сбросить задачу → нужен безопасный UX reset, согласованный с отдельным change `reset-task`.
