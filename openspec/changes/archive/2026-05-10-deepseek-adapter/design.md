## Context

Система уже движется к модели “один общий LLM-слой + несколько отдельных адаптеров”. DeepSeek должен добавляться именно как отдельный адаптер, а не как разрастание существующих интеграций OpenAI или Ollama.

## Goals / Non-Goals

**Goals:**
- Добавить отдельный адаптер для DeepSeek.
- Перенести выбор активного LLM-провайдера в `desengine.config.txt`, чтобы оператор переключал провайдер и модель без правок `desengine.config.json`.
- Собрать общий registry-слой адаптеров, пригодный для следующего подключения Gemini API.
- Зафиксировать минимальную конфигурацию и способ авторизации.
- Подключить `start` и `iterate` к этому адаптеру через единый LLM-слой.

**Non-Goals:**
- Одновременная реализация других провайдеров в этом change.
- Унификация всех провайдеров до полного общего формата без provider-specific логики.
- Автоматический импорт всех моделей провайдера без явного решения.

## Decisions

- DeepSeek добавляется как отдельный адаптер в существующую модель провайдеров.
- Активный провайдер выбирается через `DESENGINE_LLM_PROVIDER` в `desengine.config.txt`.
- Provider-specific переменные именуются через namespace провайдера и могут сосуществовать в одном `desengine.config.txt` без конфликта.
- Авторизация выполняется по API key DeepSeek.
- Endpoint и формат запросов следуют API DeepSeek.
- Минимальная конфигурация включает API key, model и базовый URL провайдера.
- `desengine.config.json` не должен определять активный provider или модель LLM, чтобы не спорить с локальным env-конфигом.
- Даже если часть интерфейса выглядит совместимой с уже известными API, режим DeepSeek должен оставаться отдельным режимом провайдера.
- Если текущий доступный API DeepSeek не принимает входные изображения уровня, адаптер может работать в text-only режиме, но обязан делать это явно и без конфликтов с другими провайдерами.

## Risks / Trade-offs

- [Provider-specific API] → адаптер неизбежно содержит знание о формате конкретного провайдера → это допустимо, потому что каждый провайдер идёт отдельным change.
- [Переключение провайдеров] → при хранении нескольких ключей в одном `desengine.config.txt` легко получить двусмысленность → активным считается только provider из `DESENGINE_LLM_PROVIDER`, а проверки готовности и сетевой доступности выполняются только для него.
- [Несовпадение метрик] → токены, стоимость и диагностические поля могут отличаться от OpenAI → общий LLM-слой должен уметь хранить “метрики есть / метрик нет”.
- [Изменения API провайдера] → provider-specific интеграция может требовать доработок → изоляция в отдельном адаптере уменьшает область изменений.
