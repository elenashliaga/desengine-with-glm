## Why

Сейчас в репозитории смешаны два разных типа данных:
- проектные и учебные данные, которые должны приходить из Git и обновляться вместе с кодом;
- пользовательское состояние, которое возникает уже во время реального прохождения задач.

На практике это означает, что:
- прогресс пользователя лежит в `env/user-progress.json`;
- рабочие файлы задачи, prompt-history и результаты LLM-запусков лежат прямо внутри `tasks/<taskId>/`;
- обновление проекта из Git рискует пересекаться с пользовательскими артефактами;
- полная очистка пользовательских результатов не отделена от проектных данных.

Команда хочет развести эти два слоя: настройки уровней и задач должны оставаться проектными данными, а весь реальный прогресс и созданные пользователем файлы должны жить отдельно в `/user`.

## What Changes

- Фиксируем разделение между project data и user state.
- Фиксируем, что:
  - настройки уровней остаются в `levels/`;
  - настройки задач и базовые референсы остаются в проектных каталогах задач;
  - весь реальный пользовательский прогресс и все рабочие файлы, созданные по ходу решения задач, переносятся в `/user`.
- Фиксируем, что каталог `/user` не должен затрагиваться обычным обновлением проекта из GitHub.
- Фиксируем, что отсутствие каталога `/user` не считается фатальной ошибкой:
  - система должна пересоздавать его по необходимости;
  - полное удаление `/user` должно означать просто полный сброс пользовательских результатов и прогресса.

## Capabilities

### New Capabilities
- `user-state-storage`: отдельное хранение пользовательского состояния вне project data.

### Modified Capabilities
- `task`: рабочие файлы задачи и результаты решения больше не должны смешиваться с проектным описанием задачи.
- `user-progress`: прогресс пользователя должен храниться в отдельном пользовательском каталоге.
- `external-local-onboarding`: локальная установка должна явно различать проектные данные и пользовательское состояние.

## Impact

- Storage layout: потребуется ввести новый каталог `/user` и новую карту путей для runtime-состояния.
- Repository hygiene: `user/` нужно исключить из обычного project-tracked слоя, чтобы обновления из GitHub не трогали пользовательские данные.
- Reset semantics: удаление `user/` должно приводить к чистому старту, а не к поломке приложения.
- Docs/OpenSpec: документацию и спеки нужно обновить под новую модель хранения.
