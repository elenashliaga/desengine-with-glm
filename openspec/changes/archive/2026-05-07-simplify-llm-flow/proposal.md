## Why

Текущая модель работы с LLM стала избыточной: отдельно обсуждаются локальные адаптеры, отдельные модели для инициирующего и уточняющего потоков, а картинки не прикладываются к обычным уточнениям. Это усложняет продуктовую модель и делает поведение менее прозрачным для пользователя.

## What Changes

- Оставляем одну и ту же модель для инициирующего запуска и для обычных уточняющих запросов.
- Убираем поддержку локальных моделей и локальных endpoint'ов.
- Оставляем только сетевые LLM-провайдеры, доступные по ключу.
- Отменяем правило, по которому к уточняющим запросам картинки не прикладываются.
- Фиксируем, что к каждому уточняющему запросу прикладываются все картинки, которые разрешено показывать пользователю на текущем уровне задачи.

### Modified Capabilities
- `llm`: система использует только сетевые провайдеры по ключу и одну модель на `start` и `iterate`.
- `iteration`: уточняющие запросы всегда получают level-разрешённые картинки, а отдельная модель для initiator-потока убирается.

## Impact

- Конфигурация: потребуется убрать раздельные настройки моделей для инициирующего и уточняющего потоков.
- Архитектура: потребуется убрать локальные режимы подключения и завязку на локальные endpoint'ы.
- Prompting: потребуется изменить контракт уточняющих запросов и всегда прикладывать level-разрешённые картинки.
- UI/UX: поведение LLM станет проще для объяснения пользователю и для диагностики ошибок.
