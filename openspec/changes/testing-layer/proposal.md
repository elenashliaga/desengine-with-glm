## Why

Сейчас OpenSpec фиксирует требования и сценарии поведения, но не даёт гарантий, что эти сценарии реально исполняются в тестах. В результате:

- спецификации могут «расходиться» с реальным поведением;
- changes можно закрыть без интеграции тестирования в общий контур;
- регрессии по уже описанным сценариям обнаруживаются поздно и вручную.

Нужен отдельный, единый слой тестирования, который:

- связывает OpenSpec specs с тестами (traceability);
- обеспечивает минимальный «обязательный» набор тестов для каждого спек-домена;
- даёт единые команды запуска и правила добавления тестов при каждом новом change.

## What Changes

- Вводим «единый слой тестирования» для системы на базе существующего стека (Vitest/Playwright) без изменения install-critical инфраструктуры.
- Покрываем все `openspec/specs/**` необходимыми тестами:
  - каждый spec имеет набор тестов, достаточный для проверки ключевых сценариев;
  - фиксируем минимальную планку покрытия (по требованиям/сценариям) и формат привязки тестов к спеку.
- Вводим правило: любой новый change должен включать задачи и требования, обеспечивающие интеграцию тестирования этого change в единый слой.
- Добавляем механизм credentials для тестов (если нужен доступ к внешним сервисам) и правила работы с mock-данными:
  - не храним секреты в репозитории;
  - для локального запуска используем `.env.local`/переменные окружения и безопасные заглушки;
  - предоставляем детерминированные mock/fixture-данные для воспроизводимости.
- Пишем инструкцию по тестированию и добавляем (при необходимости) отдельные команды/скрипты для запуска:
  - быстрый прогон «слоя» (smoke) и полный прогон;
  - запуск тестов по конкретному spec/capability;
  - CI-режим (если применимо).

## Capabilities

### New Capabilities
- `testing-layer`: единый слой тестирования, который обеспечивает запуск и поддержку тестов, связанных со спецификациями OpenSpec.

### Modified Capabilities
- `openspec`: изменения в правилах разработки — для каждого нового change требуется интеграция тестирования в общий слой.

## Impact

- Тестовая инфраструктура:
  - потребуется договориться о структуре каталога тестов «по спекам» и формате ссылок на spec-файлы;
  - потребуется общий набор утилит (helpers/fixtures) и единый runner/команды.
- Документация:
  - нужна инструкция для разработчиков по запуску слоя и по добавлению тестов к specs/changes.
- Credentials:
  - потребуется безопасный способ предоставления секретов для тестов (через env и локальные файлы конфигурации).
