## Context

Система уже движется к модели “один общий LLM-слой + несколько отдельных адаптеров”. xAI Grok должен добавляться именно как отдельный адаптер, а не как разрастание существующих интеграций OpenAI или Ollama.

## Goals / Non-Goals

**Goals:**
- Добавить отдельный адаптер для xAI Grok.
- Зафиксировать минимальную конфигурацию и способ авторизации.
- Подключить `start` и `iterate` к этому адаптеру через единый LLM-слой.

**Non-Goals:**
- Одновременная реализация других провайдеров в этом change.
- Унификация всех провайдеров до полного общего формата без provider-specific логики.
- Автоматический импорт всех моделей провайдера без явного решения.

## Decisions

- xAI Grok добавляется как отдельный адаптер в существующую модель провайдеров.
- Авторизация выполняется по API key xAI.
- Endpoint и формат запросов следуют API xAI.
- Минимальная конфигурация включает API key, model и базовый URL провайдера.
- Адаптер должен быть выделен отдельно, даже если часть интерфейса выглядит совместимой с уже известными API.

## Risks / Trade-offs

- [Provider-specific API] → адаптер неизбежно содержит знание о формате конкретного провайдера → это допустимо, потому что каждый провайдер идёт отдельным change.
- [Несовпадение метрик] → токены, стоимость и диагностические поля могут отличаться от OpenAI → общий LLM-слой должен уметь хранить “метрики есть / метрик нет”.
- [Изменения API провайдера] → provider-specific интеграция может требовать доработок → изоляция в отдельном адаптере уменьшает область изменений.
