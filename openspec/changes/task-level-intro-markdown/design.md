## Context

Сейчас task-level пояснение живёт в `config.json` как `levelTaskNotes`. Такой формат подходит для коротких строк, но плохо масштабируется на полноценные учебные тексты, где нужны:
- ссылки;
- абзацы;
- списки;
- более свободный редакторский формат.

При этом эти пояснения не относятся к скрытому prompt-контуру. Это открытый пользовательский контент, который нужно хранить рядом с onboarding-материалами задачи как отдельные файлы.

## Goals / Non-Goals

**Goals:**
- Вынести task-level пользовательские пояснения из JSON в отдельные Markdown-файлы.
- Зафиксировать стабильный путь `onboarding/tasks/<taskId>/levels/<levelId>/tip.md`.
- Отделить пользовательские tip-материалы от LLM prompt-контекста.
- Разрешить отсутствие файла как валидное пустое состояние.

**Non-Goals:**
- Перенос hidden prompt-материалов задачи в этот каталог.
- Обязательность tip-файла для каждого уровня.
- Богатый WYSIWYG-редактор или новый формат besides Markdown.

## Decisions

- Task-level tip хранится как отдельный Markdown-файл.
  - Канонический путь: `onboarding/tasks/<taskId>/levels/<levelId>/tip.md`.
  - Этот файл относится к открытому onboarding-контенту задачи.

- Tip-файл используется только в пользовательском интерфейсе.
  - Он не должен автоматически попадать в start- или iterate-prompt.
  - Это именно совет и пояснение для человека, а не часть скрытой генеративной логики.

- Отсутствие `tip.md` допустимо.
  - Если файл не существует, система показывает пустое task-specific пояснение уровня.
  - Отсутствие файла не считается ошибкой onboarding-контента.

- Task config перестаёт быть единственным носителем level-specific пояснений.
  - Приоритетный открытый формат для пользовательского tip — Markdown-файл.
  - Дальнейшая судьба `levelTaskNotes` как legacy/fallback может быть решена в реализации, но новый контракт уже должен опираться на `tip.md`.

## Pre-Implementation Checklist

- Проверить, где сейчас task-specific пояснение уровня читается из `levelTaskNotes`.
- Зафиксировать, будет ли `levelTaskNotes` временным fallback или сразу уйдёт из runtime-контракта.
- Поддержать безопасное чтение `tip.md` с пустым fallback.
- Проверить, что Markdown-рендер user-facing tip не вмешивается в prompt-контекст.

## Risks / Trade-offs

- [Переходный период] → можно временно получить два источника task-level пояснений (`levelTaskNotes` и `tip.md`) → нужно явно выбрать приоритет в runtime.
- [Markdown как открытый контент] → нужно аккуратно определить способ рендера в UI → это нормально, потому что формат предназначен именно для пользовательского чтения.
- [Пустой файл или отсутствие файла] → разные уровни будут выглядеть по-разному по насыщенности → это допустимо и прямо входит в контракт.
