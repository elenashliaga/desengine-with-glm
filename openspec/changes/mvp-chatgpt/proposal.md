## Why

Нужно как можно быстрее получить работающий “производственный” MVP: пользователь даёт PNG и промпт, система через ChatGPT API возвращает обновлённый набор файлов компонента и позволяет повторять итерации.

## What Changes

- Добавляем MVP‑подключение к ChatGPT API по ключу.
- Фиксируем контракт итерации: один запуск может обновить несколько файлов (по умолчанию — весь набор).
- Фиксируем контракт слепка: публикуются итоговые файлы + история промптов, без секретов.
- Добавляем минимальный учёт затрат на итерацию и на задание.

### Modified Capabilities
- `llm`: на MVP провайдером является ChatGPT API; требуется безопасное хранение ключа, понятные ошибки и учёт затрат.
- `iteration`: итерация должна принимать PNG + историю промптов + выбранные вводные файлы и возвращать обновления нескольких файлов за один запуск.
- `snapshot`: слепок включает итоговые файлы + историю промптов и исключает секреты.
- `task`: PNG обязателен для запуска итераций.

## Impact

- API/инфраструктура: потребуется хранение ключа ChatGPT API и обработка ошибок провайдера.
- UI/UX: потребуется понятный статус итерации, а также отображение ошибок и затрат.
- Хранилище: потребуется локальное хранение истории промптов и метрик затрат по заданию.
