## MODIFIED Requirements

### Requirement: Версионируемый шаблон локальной конфигурации явно объясняет первый шаг

Система SHALL хранить шаблон локальной конфигурации в `desengine.config-example.txt`, явно объяснять в нём, что файл нужно переименовать в `desengine.config.txt`, и держать в шаблоне канонический `DESENGINE_ONBOARDING_REPO_URL`, из которого официальная установка получает первый `/onboarding`.

#### Scenario: Пользователь открывает шаблон конфигурации
- **WHEN** пользователь открывает `desengine.config-example.txt`
- **THEN** в первой строке он видит комментарий о переименовании файла в `desengine.config.txt`
- **AND** видит в шаблоне значение `DESENGINE_ONBOARDING_REPO_URL`, которое задаёт канонический источник первичной загрузки `/onboarding`

### Requirement: Локальная система читает onboarding-контент только из `/onboarding`

Система SHALL в этой фазе локальной миграции читать onboarding-контент только из `/onboarding`, не переключаться на старые корневые каталоги и не считать установку готовой, пока `/onboarding` не синхронизирован с репозиторием, указанным в `DESENGINE_ONBOARDING_REPO_URL`.

#### Scenario: Локальная установка ещё не получила полный `/onboarding`
- **WHEN** пользователь запускает продукт без полного onboarding-контента в `/onboarding`
- **THEN** система не переключается на старые корневые каталоги
- **AND** явно показывает проблему с onboarding-контентом
- **AND** не считает установку корректно завершённой

## ADDED Requirements

### Requirement: Официальная установка гарантирует первичную загрузку `/onboarding` из шаблонно заданного репозитория

Система SHALL в официальном сценарии установки гарантировать, что первый локальный `/onboarding` загружен из репозитория, заданного через `DESENGINE_ONBOARDING_REPO_URL` в шаблонной конфигурации и затем перенесённого в `desengine.config.txt`.

#### Scenario: Пользователь проходит новую установку по шаблонной конфигурации
- **WHEN** пользователь создаёт `desengine.config.txt` из `desengine.config-example.txt` и запускает официальный сценарий установки
- **THEN** система загружает `/onboarding` из репозитория, указанного в `DESENGINE_ONBOARDING_REPO_URL`
- **AND** только после этого считает локальную установку готовой

#### Scenario: Локальный `/onboarding` пришёл не из того репозитория
- **WHEN** в локальной установке уже есть `/onboarding`, но он не соответствует репозиторию из `DESENGINE_ONBOARDING_REPO_URL`
- **THEN** система явно сообщает о mismatch источника
- **AND** предлагает пересинхронизировать `/onboarding` из канонического репозитория

### Requirement: Канонические инструкции локального запуска согласованы между собой

Система SHALL поддерживать `README.md`, `INSTALL.md` и релевантные документы из `docs/**` в согласованном состоянии, чтобы они описывали один и тот же актуальный локальный пользовательский и административный поток.

#### Scenario: Команда перепроверяет документацию локального запуска
- **WHEN** команда читает `README.md`, `INSTALL.md` и документы из `docs/**`, связанные с локальным запуском
- **THEN** они не противоречат друг другу по маршрутам, конфиг-файлам, onboarding-потоку и allowlist-потоку

### Requirement: Инструкции локального запуска явно разделяют пользовательский и административный контуры

Система SHALL в канонической документации явно разделять шаги пользователя и администратора, чтобы человек понимал, какие действия относятся к его роли.

#### Scenario: Читатель открывает инструкцию первого запуска
- **WHEN** пользователь или администратор читает root- или docs-инструкцию
- **THEN** документ явно показывает, какие шаги относятся к пользователю, а какие к администратору
- **AND** не смешивает browser-only пользовательский поток со служебными настройками и командами сопровождения

### Requirement: Корневые документы направляют читателя по канонической карте документации

Система SHALL использовать `README.md` и `INSTALL.md` как канонические точки входа и явно направлять читателя к профильным документам в `docs/**`, когда нужны детали.

#### Scenario: Читателю нужны подробности по частной теме
- **WHEN** root-документ доходит до темы allowlist, LLM-провайдера, platform notes или admin tools
- **THEN** он ссылается на соответствующий специализированный документ
- **AND** не пытается дублировать его полностью
