# Admin Tools

## Purpose

Зафиксировать единый каталог, документацию и способ запуска канонических админских утилит репозитория.

## Requirements

### Requirement: Админские утилиты имеют единый каталог

Система SHALL хранить канонические админские утилиты в каталоге `/tools`.

#### Scenario: Оператор ищет служебную утилиту
- **WHEN** оператору нужен официальный админский скрипт
- **THEN** он находит его в `/tools`

### Requirement: Инструкции по admin tools живут рядом с инструментами

Система SHALL хранить каноническую Markdown-инструкцию по админским утилитам внутри `/tools`.

#### Scenario: Оператор ищет инструкцию по служебной команде
- **WHEN** оператору нужна инструкция по использованию admin tool
- **THEN** он находит её в Markdown-файле внутри `/tools`

### Requirement: Канонический запуск admin tools идёт через npm

Система SHALL использовать `npm run ...` как канонический entry point для админских утилит.

#### Scenario: Оператор запускает служебную утилиту
- **WHEN** оператор использует официальный admin tool
- **THEN** он запускает его через `npm run ...`

### Requirement: Bash-утилиты не являются каноническим admin entry point

Система SHALL не считать bash-скрипты официальным способом запуска админских утилит после миграции.

#### Scenario: В репозитории существует исторический shell-скрипт
- **WHEN** оператор ищет канонический способ выполнить соответствующее действие
- **THEN** он использует JS-утилиту и `npm run ...`, а не прямой bash-скрипт
