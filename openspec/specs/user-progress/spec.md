# Пользователь и прогресс

На MVP система ориентирована на локальную работу одного пользователя на своей машине.

## Purpose

Зафиксировать, что такое “пользователь” и “прогресс” на MVP, и какие данные прогресса считаются локальными и непубличными по умолчанию.

## Requirements

### Requirement: На MVP пользователь локальный и один

Система SHALL поддерживать локальную работу одного пользователя на одной машине на MVP.

#### Scenario: Пользователь использует систему локально
- **WHEN** пользователь работает с заданиями
- **THEN** система не требует аккаунта/серверной регистрации на MVP

### Requirement: Прогресс хранится локально

Система SHALL хранить прогресс локально и не публиковать его автоматически.

Локальный прогресс SHALL храниться в user-owned каталоге `user/`, а не рядом с versioned project data.

#### Scenario: Runtime читает и пишет пользовательский прогресс
- **WHEN** приложение загружает или сохраняет прогресс пользователя
- **THEN** оно использует `user/user-progress.json`
- **AND** не использует `env/user-progress.json` как рабочее хранилище прогресса


### Requirement: Прогресс хранит checking-state текущего уровня

Система SHALL хранить для текущего уровня число содержательных проверок и явный пользовательский статус ожидания повторной проверки.

#### Scenario: Проверка завершилась техническим сбоем
- **WHEN** checking run не состоялся технически
- **THEN** локальный progress не увеличивает счётчик содержательных проверок
- **AND** отражает пользовательский статус `Ждёт проверки`

#### Scenario: Пользователь видит задачу после технического сбоя проверки
- **WHEN** текущий уровень ждёт повторной проверки
- **THEN** интерфейс может показать пользователю статус `Ждёт проверки`
- **AND** этот статус не считается завершением уровня

#### Scenario: Исчерпан лимит содержательных проверок уровня
- **WHEN** последняя доступная содержательная проверка уровня завершилась неуспешно
- **THEN** система сбрасывает задачу в состояние `Не начиналась`
- **AND** прогресс этой задачи больше не считается начатым

### Requirement: Прогресс отображается на стартовой странице задач

Система SHALL показывать прогресс пользователя по задачам на стартовой странице.

Для начатой задачи система SHALL показывать текущий уровень, остаток уточняющих запросов на текущем уровне и горизонтальный индикатор, длина которого растёт вместе с уровнем.

#### Scenario: Пользователь открывает стартовую страницу
- **WHEN** у пользователя есть начатые задачи
- **THEN** система показывает для каждой начатой задачи её текущий уровень
- **AND** показывает, сколько уточняющих запросов осталось на текущем уровне
- **AND** показывает горизонтальный индикатор уровня

#### Scenario: Следующий уровень уже стал текущим, но ещё не начат
- **WHEN** пользователь успешно завершил предыдущий уровень
- **AND** ещё не запустил новый текущий уровень
- **THEN** прогресс показывает задачу как начатую
- **AND** одновременно отражает, что текущий уровень ещё не начат

#### Scenario: У задачи более высокий уровень
- **WHEN** текущий уровень одной задачи выше, чем у другой
- **THEN** горизонтальный индикатор первой задачи визуально длиннее

### Requirement: Прогресс задачи не хранит отдельную completion-причину уровня

Система SHALL определять завершение текущего уровня задачи по статусу уровня (`status = completed`) без дополнительного поля `completionReason` в task-progress.

#### Scenario: Уровень успешно завершён
- **WHEN** содержательная проверка уровня завершилась успешно
- **THEN** система отмечает уровень как `completed`
- **AND** не записывает отдельную completion-причину в progress

#### Scenario: Runtime читает локальный task-progress
- **WHEN** приложение загружает прогресс задачи
- **THEN** модель task-progress не требует поля `completionReason`
- **AND** отображение статуса уровня строится по status/checking-state/лимитам

### Requirement: Прогресс уровня хранит явный признак прохождения

Система SHALL хранить в прогрессе каждого уровня задачи явное булево поле `isPassed`, отражающее факт прохождения уровня.

#### Scenario: Уровень успешно проверен
- **WHEN** содержательная проверка уровня завершилась успешно
- **THEN** уровень помечается как `isPassed = true`
- **AND** уровень имеет статус `completed`

### Requirement: Система восстанавливает прохождение уровня из persisted данных

Система SHALL при чтении локального прогресса уметь восстановить пройденность уровня, если она подтверждается сохранёнными артефактами проверки.

#### Scenario: В check-result есть успешное прохождение
- **WHEN** у задачи есть `check-result` с `passed=true` и `kind=passed`
- **THEN** соответствующий уровень помечается как пройденный (`isPassed=true`, `status=completed`)
- **AND** текущий уровень задачи продвигается до следующего после пройденного

### Requirement: Reset возвращает задачу в состояние `Не начиналась`

Система SHALL уметь возвращать задачу в состояние `Не начиналась` после reset.

#### Scenario: Пользователь сбрасывает задачу
- **WHEN** reset задачи завершён
- **THEN** система считает эту задачу не начатой
- **AND** следующий вход в задачу проходит обычный стартовый сценарий

### Requirement: Удаление `user/` не ломает систему

Система SHALL трактовать отсутствие user-owned каталога `user/` как валидное нулевое состояние.

#### Scenario: Пользователь удалил каталог `user/`
- **WHEN** приложение запускается после полного удаления `user/`
- **THEN** система не падает
- **AND** считает все задачи не начатыми
- **AND** пересоздаёт нужные user-owned данные только по мере дальнейшей работы

## Прогресс (что это)

“Метаданные прогресса” — это служебная информация о том, как пользователь продвигается по заданиям.

Примеры метаданных (не все обязательны на MVP):
- статус задания: не начато / в работе / завершено;
- номер последней итерации;
- дата/время последней активности;
- заметка пользователя (опционально);
- текущий уровень пользователя внутри задачи;
- статус текущего уровня задачи;
- число использованных промптов на текущем уровне.
- число оставшихся промптов на текущем уровне.
- число содержательных проверок текущего уровня;
- признак того, что текущий уровень ждёт повторной проверки.

## Требования (MVP)

- Прогресс хранится локально.
- Прогресс не виден другим пользователям (так как других пользователей на MVP нет).
- Прогресс должен хранить для каждой задачи текущий уровень, статус уровня, число использованных промптов на этом уровне и вычислимый остаток промптов текущего уровня.
- Прогресс должен хранить для текущего уровня число содержательных проверок и checking-state.
