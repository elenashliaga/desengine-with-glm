# Уровни задач

Уровни являются общей образовательной осью продукта. Они одинаковы для всех задач как типы обучения, но каждая конкретная задача имеет собственную глубину прохождения по уровням.

## Purpose

Определить глобальный каталог уровней, правила перехода одной и той же задачи между уровнями и минимальный экран уровня.

## Requirements

### Requirement: Уровни являются глобальными для всей системы

Система SHALL поддерживать общий каталог уровней, единый для всех задач.

#### Scenario: Система читает каталог уровней
- **WHEN** система загружает конфигурацию уровней
- **THEN** каждый уровень имеет глобальный `levelId`
- **AND** каждый уровень имеет человекочитаемые `title` и `description`
- **AND** каждый уровень может иметь необязательный открытый `url`
- **AND** каталог уровней не зависит от конкретной задачи

### Requirement: Каталог уровней поддерживает открытый URL-параметр уровня

Система SHALL поддерживать в метаданных уровня явный URL-параметр как часть открытого каталога уровней.

#### Scenario: Runtime загружает каталог уровней
- **WHEN** система читает level metadata
- **THEN** она может получить для уровня значение `url`
- **AND** отсутствие этого значения не считается ошибкой

### Requirement: Каждая задача имеет собственный диапазон уровней

Система SHALL хранить для каждой задачи её максимальный уровень `maxLevel`.

#### Scenario: Система читает метаданные задачи
- **WHEN** система загружает описание задачи
- **THEN** задача существует на уровнях от `1` до `maxLevel`

### Requirement: Пользователь проходит одну и ту же задачу последовательно

Система SHALL переводить пользователя внутри одной и той же задачи с уровня `L` на уровень `L+1`, если следующий уровень существует.

#### Scenario: Пользователь завершил текущий уровень задачи
- **WHEN** уровень `L` завершён
- **THEN** система переводит пользователя на уровень `L+1` этой же задачи

### Requirement: Каждый уровень начинается со скрытого инициирующего запуска

Система SHALL выполнять для каждого уровня задачи отдельный инициирующий запуск до первых уточняющих промптов пользователя.

#### Scenario: Пользователь впервые входит в новый уровень задачи
- **WHEN** пользователь открывает задачу на уровне `L`, который ещё не был инициализирован
- **THEN** система выполняет скрытый инициирующий запуск этого уровня
- **AND** только после него разрешает обычные уточняющие промпты

### Requirement: Каждый уровень определяет допустимые рабочие файлы задачи

Система SHALL определять для каждого уровня задачи список разрешённых рабочих `fileId`.

#### Scenario: Система загружает конфигурацию уровня
- **WHEN** система читает уровень задачи
- **THEN** ей известен allowlist рабочих файлов этого уровня

### Requirement: Переход на уровень приводит рабочую директорию к allowlist этого уровня

Система SHALL при входе на уровень приводить рабочие файлы задачи к набору, разрешённому для этого уровня.

#### Scenario: Новый уровень запрещает файл, существовавший раньше
- **WHEN** пользователь входит на уровень, где часть прежних рабочих файлов больше не разрешена
- **THEN** система удаляет эти рабочие файлы из директории задачи
- **AND** продолжает подготовку уровня

### Requirement: Переход между уровнями проходит через отдельный экран

Система SHALL показывать экран перехода перед открытием следующего уровня той же задачи.

#### Scenario: У задачи есть следующий уровень
- **WHEN** пользователь завершил задачу на уровне `L`
- **THEN** система сначала показывает экран перехода
- **AND** только после явного действия открывает уровень `L+1`

### Requirement: Завершение уровня требует отдельной успешной проверки

Система SHALL считать уровень завершённым только после успешной проверки результата уровня.

#### Scenario: Пользователь нажал `Я закончил`
- **WHEN** пользователь на текущем уровне запускает действие `Я закончил`
- **THEN** система запускает проверку результата уровня
- **AND** ещё не считает уровень завершённым только по самому нажатию кнопки

#### Scenario: Проверка уровня успешна
- **WHEN** checking run вернул `passed = true`
- **THEN** система завершает текущий уровень задачи
- **AND** только после этого открывает дальнейший flow перехода

### Requirement: Лимит уточняющих промптов не завершает уровень автоматически

Система SHALL трактовать `maxPromptsPerTask` только как ограничение на новые уточняющие промпты уровня, а не как самостоятельный критерий завершения уровня.

#### Scenario: Исчерпан лимит уточняющих промптов уровня
- **WHEN** число использованных уточняющих промптов достигло лимита текущего уровня
- **THEN** система не запускает новую итерацию
- **AND** не считает уровень завершённым только по этой причине
- **AND** сохраняет возможность пройти отдельную проверку результата уровня

### Requirement: Экран перехода имеет два действия

Система SHALL показывать на экране перехода между уровнями ровно два действия:
- `Решать эту же задачу дальше`
- `Перейти в список задач`

#### Scenario: Пользователь попал на экран перехода
- **WHEN** завершён уровень задачи и существует следующий
- **THEN** система показывает ровно эти два действия

### Requirement: Экран уровня показывает обзор задач

Система SHALL предоставлять простой экран уровня вне конкретной задачи.

#### Scenario: Пользователь открывает экран уровня
- **WHEN** пользователь открывает `/levels/<levelId>`
- **THEN** система показывает номер уровня
- **AND** система показывает описание уровня
- **AND** список задач, которые сейчас можно решать на этом уровне
- **AND** список задач, для которых этот уровень уже пройден

### Requirement: Система показывает сводную страницу по всем уровням

Система SHALL предоставлять отдельную страницу со всеми уровнями, их описаниями и задачами.

#### Scenario: Пользователь открывает общий обзор уровней
- **WHEN** пользователь открывает `/levels`
- **THEN** система показывает для каждого уровня его название и описание
- **AND** показывает задачи, доступные на этом уровне
- **AND** показывает задачи, уже прошедшие этот уровень

### Requirement: Текущий экран лаборатории восстанавливается по URL

Система SHALL кодировать текущий экран лаборатории в URL, чтобы перезагрузка страницы возвращала пользователя в тот же контекст.

#### Scenario: Пользователь перезагружает открытую задачу
- **WHEN** пользователь находится на экране конкретной задачи и обновляет страницу
- **THEN** система снова открывает ту же задачу по её path-based URL

#### Scenario: Пользователь перезагружает экран уровня
- **WHEN** пользователь находится на экране конкретного уровня и обновляет страницу
- **THEN** система снова открывает этот же уровень по его path-based URL

### Requirement: Уровни и их onboarding-материалы приходят из внешнего onboarding-слоя

Система SHALL считать конфигурацию уровней, их overview и didactic-материалы частью onboarding-репозитория.

#### Scenario: Система читает каталог уровней
- **WHEN** системе нужен каталог уровней и связанные onboarding-материалы
- **THEN** она рассматривает onboarding-репозиторий как канонический источник
