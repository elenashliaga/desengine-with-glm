# Контракт набора файлов компонента

Этот документ фиксирует, какой “набор файлов компонента” считается результатом работы системы.

## Purpose

Зафиксировать единый набор файлов React‑компонента, с которым работает система, чтобы итерации LLM и публикация слепков были однозначными и воспроизводимыми.

## Requirements

### Requirement: Набор файлов компонента фиксирован на MVP

Система SHALL оперировать фиксированным набором файлов компонента для каждого задания.

#### Scenario: Пользователь запускает итерацию по заданию
- **WHEN** пользователь запускает итерацию для задания
- **THEN** система использует фиксированный набор файлов из этого спека

### Requirement: Допустимый рабочий набор файлов зависит от текущего уровня

Система SHALL ограничивать фактический рабочий набор файлов текущего уровня только теми `fileId`, которые разрешены `editableFileIds` этого уровня.

#### Scenario: На уровне запрещён `styles`
- **WHEN** текущий уровень задачи не разрешает `fileId` `styles`
- **THEN** файл `styles.ts` не считается допустимой частью рабочего набора этого уровня
- **AND** система не должна создавать или обновлять его как результат работы LLM

### Requirement: Запрещённые рабочие файлы автоматически удаляются

Система SHALL автоматически удалять рабочие файлы из управляемого набора компонента, если они запрещены на текущем уровне.

#### Scenario: На диске остался запрещённый рабочий файл
- **WHEN** система выполняет `start` или `iterate` для уровня, где этот `fileId` запрещён
- **THEN** система удаляет соответствующий рабочий файл с диска
- **AND** продолжает работу без пользовательской ошибки

### Requirement: Пользователь выбирает вводные файлы

Система SHALL позволять пользователю выбрать подмножество файлов, которые будут включены в контекст итерации (Input files).

#### Scenario: Пользователь не выбирал вводные файлы явно
- **WHEN** пользователь не выбрал вводные файлы
- **THEN** по умолчанию в контекст итерации включаются все рабочие файлы, разрешённые на текущем уровне

### Requirement: Итерация может менять несколько выбранных файлов

Система SHALL поддерживать изменение нескольких файлов за одну итерацию, в пределах выбранных пользователем вводных файлов.

#### Scenario: Пользователь включил в вводные несколько файлов
- **WHEN** пользователь включает в вводные два и более файла
- **THEN** итерация может обновить любой из этих файлов за один запуск

## Набор файлов (MVP)

Для каждого задания система оперирует фиксированным набором файлов:
- `Component.tsx` — исходный код React‑компонента.
- `Component.stories.ts` — истории Storybook для компонента.
- `styles.ts` — стили (формат уточняется отдельно; на MVP достаточно существования файла и использования в компоненте).
- `props.ts` — контракт пропсов компонента.
- `mock.ts` — примеры данных/моки для демонстрации.

## Базовые требования к набору

- Набор должен быть самодостаточным для:
  - сборки и запуска Storybook;
  - рендера компонента в изоляции.
- Система считает эти файлы “истиной” для текущего состояния задания.

## Вводные файлы (Input files)

- Пользователь может выбрать подмножество файлов, которые будут включены как вводные в итерацию.
- По умолчанию в итерацию включаются все рабочие файлы из набора, разрешённые на текущем уровне.
- Итерация может менять все указанные пользователем вводные файлы за один запуск LLM.
