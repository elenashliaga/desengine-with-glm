# UI Foundation

## Purpose

Зафиксировать единый контракт использования надёжных framework/UI-компонентов в интерфейсе собственной оболочки системы.

## Requirements

### Requirement: Интерфейс инструмента использует единый Tailwind UI-слой

Система SHALL поддерживать единый Tailwind CSS-слой для общего визуального языка интерфейса инструмента.

Под интерфейсом инструмента в этом контракте понимаются продуктовые маршруты `app/**` и используемые ими оболочечные компоненты из `components/desengine/**`.

#### Scenario: Разработчик добавляет новый product-shell экран
- **WHEN** новый экран использует типовые визуальные паттерны интерфейса инструмента
- **THEN** он опирается на общий Tailwind UI-слой, а не собирает эти паттерны заново длинными inline class string

#### Scenario: Разработчик переносит повторяющийся shell-паттерн
- **WHEN** один и тот же визуальный паттерн повторяется на нескольких product-shell экранах или в нескольких оболочечных компонентах
- **THEN** он выносится в единый Tailwind UI-слой интерфейса инструмента

#### Scenario: Команда проверяет новый shell-экран в review
- **WHEN** в `app/**` или `components/desengine/**` появляется новый page, section, card, link или status/notice-паттерн
- **THEN** review проверяет, что повторяющееся решение использует единый Tailwind UI-слой интерфейса инструмента
- **AND** локальная inline-стилизация оставлена только для компонентно-специфичного остатка

### Requirement: Локальные styles.ts ограничены индивидуальной стилизацией компонента

Система SHALL использовать локальные `styles.ts` в product-shell интерфейсе только для индивидуальных особенностей конкретного компонента, а не как основное место хранения общих shell-паттернов.

#### Scenario: Компонент имеет уникальную внутреннюю композицию
- **WHEN** стили относятся только к одному конкретному компоненту и не образуют общий shell-паттерн
- **THEN** они могут оставаться в локальном `styles.ts`

#### Scenario: Компонент повторяет общий shell-паттерн
- **WHEN** локальный `styles.ts` хранит стили типовой карточки, секции, страницы, action-row, ссылки или другого повторяющегося shell-паттерна
- **THEN** такой паттерн должен быть перенесён в единый Tailwind UI-слой

### Requirement: Единый Tailwind UI-слой не затрагивает учебные и пользовательские компоненты

Система SHALL ограничивать единый Tailwind UI-слой интерфейса инструмента только product-shell контуром и не распространять его как обязательный контракт на учебные и пользовательские рабочие компоненты.

#### Scenario: Команда работает с onboarding- или user-контентом
- **WHEN** изменения касаются `/onboarding/**` или генерируемых пользовательских файлов
- **THEN** требования единого Tailwind UI-слоя интерфейса инструмента не навязывают этим файлам миграцию в общий shell-стайлслой

#### Scenario: Команда проверяет границы миграции
- **WHEN** выполняется перенос повторяющихся стилей в единый UI-слой
- **THEN** scope миграции ограничен `app/**` и `components/desengine/**`
- **AND** `/onboarding/**` и `/user/**` остаются вне этого контракта

### Requirement: Интерфейс системы использует надёжные framework/UI-компоненты по умолчанию

Система SHALL в интерфейсе собственной оболочки по умолчанию использовать общепринятые надёжные framework/UI-компоненты, если для соответствующей задачи уже есть канонический эквивалент.

Под интерфейсом собственной оболочки понимаются продуктовые маршруты `app/**` и используемые ими оболочечные компоненты из `components/desengine/**`. Содержимое `/user/**` и `components/ui/**` не являются scope миграции по этому контракту.

#### Scenario: Разработчик добавляет новый элемент системного интерфейса
- **WHEN** для этой задачи уже существует канонический framework/UI-компонент
- **THEN** системный интерфейс использует его, а не сырой HTML-элемент

### Requirement: Навигация использует канонические framework-компоненты

Система SHALL использовать канонические navigation/image-компоненты экосистемы Next.js там, где они релевантны для интерфейса системы.

#### Scenario: Системный интерфейс рендерит ссылку перехода
- **WHEN** системный интерфейс рендерит продуктовую ссылку
- **THEN** он использует `next/link`

#### Scenario: Системный интерфейс рендерит изображение
- **WHEN** системный интерфейс рендерит продуктовое изображение
- **THEN** он использует `next/image`, если для этого экрана нет явного исключения

### Requirement: Базовые controls интерфейса используют shadcn/ui

Система SHALL использовать shadcn/ui-компоненты для базовых action/form controls системного интерфейса там, где такие компоненты уже существуют в проекте.

#### Scenario: Системный интерфейс рендерит кнопку или форму
- **WHEN** для нужного control уже существует shadcn/ui-компонент
- **THEN** интерфейс использует этот компонент вместо сырого HTML-аналога

#### Scenario: Команда проверяет новый product-shell UI в review
- **WHEN** в product-shell интерфейсе появляется новый action-, form- или navigation-элемент
- **THEN** review проверяет, что для него не был выбран сырой HTML-элемент при наличии канонического framework/UI-компонента

### Requirement: Системный UI использует надёжные shell-компоненты

Система SHALL рассматривать file-switcher и действия кодовой панели как важную часть shell-UI, а не как второстепенный техслой.

#### Scenario: Пользователь видит переключатели файлов
- **WHEN** task-экран показывает file-switcher
- **THEN** переключатели выглядят как аккуратный системный control
- **AND** не выбиваются по стилю из остального интерфейса инструмента

#### Scenario: Пользователь видит действия кодовой панели
- **WHEN** task-экран показывает действия вроде `Скопировать`
- **THEN** эти действия встроены в shell-UI
- **AND** читаются как часть основного интерфейса инструмента

### Requirement: Локальный UI-слой поддерживает barrel-реэкспорт

Система SHALL поддерживать локальный barrel-файл для `components/ui`, чтобы проект мог импортировать уже установленные UI-компоненты как пофайлово, так и через единый модуль реэкспорта.

#### Scenario: Разработчик импортирует несколько UI-компонентов
- **WHEN** в проекте уже существуют установленные компоненты в `components/ui/**`
- **THEN** разработчик может импортировать их либо через прямой путь файла, либо через `@/components/ui`
- **AND** этот barrel-слой не заменяет copy/paste-модель shadcn/ui, а лишь реэкспортирует уже существующие локальные файлы
