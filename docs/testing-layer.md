# Единый слой тестирования (черновик)

Этот документ описывает целевой подход к «единому слою тестирования», ориентированному на OpenSpec specs, а также даёт минимальные команды для локального запуска текущего тестового стека.

## Цели

- Связать OpenSpec specs с тестами (traceability).
- Обязать каждый новый change включать тестовые задачи и проверку интеграции в общий слой.
- Сделать запуск тестов предсказуемым: быстрый прогон (smoke), полный прогон, выборка по spec/capability.

## Текущее состояние стека

В репозитории настроен Vitest (`vitest.config.ts`) с проектами:

- `unit`: Node-окружение, тесты ищутся по шаблону `lib/**/*.test.ts`
- `storybook`: браузерные тесты Storybook (Playwright provider)

## Быстрый старт: локальный запуск

### Unit

```bash
npx vitest --project unit
```

Запуск конкретного теста/группы:

```bash
npx vitest --project unit -t "часть названия"
```

### Storybook (browser)

```bash
npx vitest --project storybook
```

Если потребуется визуальный дебаг, можно временно отключить headless (на этапе реализации слоя — оформить это как отдельную команду/флаг).

## Правила для credentials

- Секреты не коммитим в репозиторий.
- Для локального запуска используем переменные окружения и/или `.env.local`.
- Для CI используем секреты окружения CI.
- Если доступ к внешнему сервису отсутствует, тесты должны иметь допустимый mock-режим (где это не нарушает смысл сценария).

Рекомендуемый подход (будет зафиксирован в реализации):

- единый файл с примером переменных: `desengine.config-example.txt` или отдельный `docs/testing-credentials.md`;
- единый список переменных окружения в OpenSpec change, где они нужны.

## Mock-данные и фикстуры

Цель — воспроизводимость:

- фикстуры должны быть детерминированными;
- генераторы данных должны быть воспроизводимыми (фиксированный seed, если применимо);
- тесты не должны зависеть от «случайного» состояния окружения.

Рекомендуемое размещение (будет уточнено в реализации):

- `test/fixtures/**`
- `test/helpers/**`

## Интеграция OpenSpec specs → тесты

Целевой контракт:

- каждый spec в `openspec/specs/**` имеет минимально необходимый набор тестов, покрывающий ключевые сценарии;
- существует проверка (скрипт/тест), что все specs имеют связанную тестовую реализацию.

Это будет реализовано в change `openspec/changes/testing-layer`.
