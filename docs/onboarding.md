# Onboarding-контент — источник и обновление

## Аудитория

- Администратор локальной установки.
- Инженер сопровождения, который проверяет источник учебных материалов и ручное обновление контента.

Пользователю этот документ обычно не нужен: в browser-only сценарии он работает только через страницы приложения.

## Роль документа

Этот файл углубляет [INSTALL.md](/Users/op/dev/sobakapav/desengine/INSTALL.md:1) и фиксирует канонический контракт для локального каталога `/onboarding`, его внешнего источника и ручного обновления через `/config`.

## Что считается каноническим источником

- Runtime читает учебные материалы из локального каталога `/onboarding`.
- Канонический внешний источник этого каталога задаётся через `DESENGINE_ONBOARDING_REPO_URL` в `desengine.config.txt`.
- Если URL не задан, система должна явно показывать, что источник onboarding-контента не настроен.

Минимальный фрагмент конфига:

```env
DESENGINE_ONBOARDING_REPO_URL=https://github.com/sobakapav/desengine-onboarding.git
```

## Что должно лежать в `/onboarding`

Система ожидает, что в локальном onboarding-каталоге доступны:

- `onboarding/levels/**`
- `onboarding/tasks/**`
- `onboarding/prompts/default.md`
- `onboarding/prompts/levels/**`

Если обязательные каталоги или файлы отсутствуют, приложение должно показать проблему в диагностике вместо тихого fallback к legacy-структуре.

## Как вручную обновить `/onboarding`

1. Убедитесь, что в `desengine.config.txt` задан `DESENGINE_ONBOARDING_REPO_URL`.
2. Запустите приложение и откройте [http://localhost:3000/config](http://localhost:3000/config).
3. Нажмите кнопку `Обновить onboarding`.
4. Дождитесь завершения операции и повторно проверьте блок диагностики onboarding-контента.

При успешном обновлении приложение заново загружает локальный `/onboarding` из внешнего репозитория. Если локальный каталог уже существовал, система сначала сохраняет его во временный backup, а затем заменяет свежим checkout.

## Что не относится к onboarding-обновлению

- Обычный `git pull` по основному репозиторию не должен считаться каноническим способом обновить учебные материалы.
- Каталог `user/` не относится к onboarding-контенту и не должен перезаписываться этой операцией.
- Browser-only пользователь не обязан знать, откуда именно приезжает `/onboarding`: его путь начинается с `/`, `/auth`, `/tasks`, `/levels`, `/help`.
