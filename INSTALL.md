# Установка desengine

Этот документ описывает локальную установку desengine для пользователя, который сам поднимает систему на своей машине.

## Что понадобится

- macOS, Windows или Linux
- актуальный `Node.js` вместе с `npm`
- браузер

`desengine` работает с локальными файлами пользователя, поэтому запуск предполагается прямо на хост-машине, а не внутри изолированного контейнера.

## 1. Установите Node.js и npm

Нужен обычный установленный `Node.js`, в комплекте с которым идёт `npm`.

Проверьте, что оба бинарника доступны:

```bash
node -v
npm -v
```

Если `node` есть, а `npm` не находится, самый надёжный путь — переустановить Node.js из одного источника, а не чинить `npm` вручную:

- либо через официальный установщик с сайта Node.js;
- либо через ваш пакетный менеджер (`brew`, `winget`, `apt`, `dnf` и т.д.).

После переустановки снова проверьте:

```bash
node -v
npm -v
```

## 2. Установите зависимости проекта

Из корня репозитория выполните:

```bash
npm --prefix lab install
```

## 3. Создайте локальную конфигурацию

Создайте файл `lab/.env.local` на основе [lab/.env.local.example](/Users/op/dev/olgapavlova/desengine/lab/.env.local.example:1).

Это можно сделать любым привычным способом:

- через проводник/Finder;
- через редактор кода;
- через командную строку, если вам так удобнее.

Минимально важные переменные:

```env
OPENAI_API_KEY=...
DESENGINE_OPENAI_MODEL=...
DESENGINE_ALLOWLIST_BASE_URL=...
DESENGINE_ALLOWLIST_SALT=...
```

Подробности:

- OpenAI: [lab/env/openai.md](/Users/op/dev/olgapavlova/desengine/lab/env/openai.md:1)
- allowlist: [lab/env/access-control.md](/Users/op/dev/olgapavlova/desengine/lab/env/access-control.md:1)

## 4. Запустите приложение

Из корня репозитория:

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) в браузере.

## 5. Что вы увидите

- На `/` сначала открывается страница состояния системы.
- До успешной allowlist-проверки рабочая часть лаборатории не откроется.
- Даже если `OPENAI_API_KEY` не задан, страница состояния всё равно должна открываться.

## Проверка перед тестированием на пользователях

Перед живым прогоном полезно проверить production-сборку:

```bash
npm run build
```

Дополнительно можно выполнить smoke-check:

```bash
npm run smoke
```

## Протокол пользовательского прогона

Если вы тестируете установку на живом человеке, попросите его идти по шагам ниже и вслух проговаривать всё, что кажется непонятным, лишним или тревожным.

Попросите пользователя:

1. Открыть этот файл и пройти установку строго по инструкции, не подглядывая в другие документы.
2. Самостоятельно проверить, есть ли у него `node` и `npm`.
3. Установить зависимости проекта.
4. Создать `lab/.env.local` на основе примера.
5. Заполнить обязательные переменные окружения.
6. Запустить приложение.
7. Открыть приложение в браузере.
8. Объяснить своими словами, что он видит на стартовом экране.
9. Попробовать пройти допуск через allowlist.
10. Сказать, в какой момент он почувствовал, что “всё работает”.

Во время прогона фиксируйте:

- на каком шаге человек остановился;
- какие слова или термины пришлось объяснять отдельно;
- понял ли человек разницу между установкой, настройкой `.env` и входом через allowlist;
- смог ли он без подсказки открыть именно корневой маршрут `/`;
- понял ли он, почему до допуска видит только страницу состояния;
- пришлось ли ему чинить `node`, `npm` или shell вручную;
- возникли ли неожиданные ошибки в `npm install`, `npm run build` или `npm run dev`.

После прогона полезно задать пользователю 3 коротких вопроса:

1. “На каком шаге инструкция перестала быть очевидной?”
2. “Что бы вы переписали в этой инструкции в первую очередь?”
3. “После этого опыта вы бы смогли повторить установку ещё раз без посторонней помощи?”

## Если что-то пошло не так

### `npm: command not found`

Значит Node.js установлен некорректно или shell не видит `npm`. Не создавайте `npm` вручную. Надёжнее переустановить Node.js целиком и убедиться, что после этого работают обе команды:

```bash
node -v
npm -v
```

### `next build` падает на TypeScript

Это уже ошибка проекта, а не установки. Сохраните хвост вывода `npm run build` и разбирайте его как обычную code/build проблему.

### Открывается только статусная страница

Это нормально, если:

- не задан `OPENAI_API_KEY`;
- не настроен allowlist;
- email ещё не прошёл allowlist-допуск.
