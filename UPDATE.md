# Обновление desengine

Этот документ описывает безопасное обновление уже установленной локальной инстанции desengine.

## Аудитория и роль

- Администратор: канонический сценарий обновления существующей установки.
- Пользователь: обновление выполняет администратор; browser-only поток остаётся прежним.

`INSTALL.md` отвечает за первый запуск, `UPDATE.md` — за последующие обновления.

## Перед началом

1. Убедитесь, что сервис не используется прямо сейчас.
2. Проверьте, что локальная конфигурация `desengine.config.txt` сохранена и актуальна.
3. Убедитесь, что понимаете границы данных:
- `user/` — пользовательское состояние и прогресс; не удалять при обычном обновлении.
- `/onboarding` — учебный контент; обновляется отдельно через `/config` (кнопка `Обновить onboarding`).

## Шаги обновления

1. Обновите код проекта из Git (ваш обычный `git pull`/merge-поток).
2. Установите зависимости:

```bash
npm install
```

3. Проверьте, что `desengine.config.txt` не потерял обязательные значения:
- `LLM_PROVIDER` и provider-specific ключ/модель/base URL;
- `ALLOWLIST_BASE_URL`, `ALLOWLIST_SALT`;
- `ONBOARDING_REPO_URL`.

4. Выполните проверки перед запуском:

```bash
npm run build
npm run smoke
```

5. Перезапустите приложение:

```bash
npm run dev
```

6. Откройте `/`, затем проверьте `/auth` и `/config`:
- статус должен быть без критических блокеров;
- допуск по allowlist должен работать;
- при необходимости вручную обновите `/onboarding` через `Обновить onboarding`.

## Что обновление не должно делать

- Не удаляйте `user/` в рамках обычного обновления.
- Не подменяйте обновление onboarding-контента обычным `git pull` по основному репозиторию.
- Не используйте release notes как замену этой инструкции.

## Быстрая диагностика после обновления

1. `/` открывается и показывает актуальный статус.
2. `/auth` принимает allowlist-email.
3. `/tasks` доступен после допуска.
4. Если onboarding неполон, `/config` явно показывает проблему и позволяет ручное обновление.

## Проверка согласованности документации

Локально можно быстро проверить, что root-документы ссылаются на сценарий обновления:

```bash
rg -n "UPDATE\\.md" README.md INSTALL.md tools/README.md docs/*.md
```
